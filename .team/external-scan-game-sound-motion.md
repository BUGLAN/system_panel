# 外部同类提示词扫描 · 第二版（卡牌 / 游戏手感 / 音响 / 动效）

> 上一版（.team/external-scan.md）扫的是前端设计类，方向不对。这一版只收「卡牌视觉 / 游戏手感 juice / 声音 / 触觉 / 动效系统」四类。
> 结论先给：外部在每一类上都有成熟做法，但没有一个把它们缝在同一张提案卡里 —— 我们的 17 栏是这四类合流的产物。

---

## 一、卡牌视觉

| 来源 | 做法 | 与我们的差异 |
|---|---|---|
| RuiC-card-skill / references/art-direction.md | 把卡拆成图层：subject / effects / background / line-art / text-and-furniture，全部落在同一张 1024×1536 竖版画布，上 15% 与下 15% 留给文字；每个图层必须给不同 depth（两层同深度=塌成一个平面，这是卡「看起来平」最常见原因）；边框图层 depth 恒为 0，所以永远焊在卡边。明确写「不要把这些烤进画里」：彩虹扫光/闪粉/星场属于材质层 | 我们是纯几何 CustomPainter、无图层无位图，他们的「分层 + depth」在我们这里等价于卡边六层的内缩顺序（docs/40 §3.3 的 L1~L6 就是这张 depth 表）。他们那条「两层同 depth 就塌」正好解释了为什么我们的 L4 厚度带是「不画的层」—— 它必须存在，否则厚度塌掉 |
| Cyberpunk TCG 可访问性文章 | 稀有度不只靠颜色：形状、图案、数量三重编码；色盲模式下改「非颜色通道」而不是加滤镜 | 与 docs/40 §3.1 三重编码同构（轮廓=归属 / 印+星轨=稀有度 / 状态线=状态）。差异：他们把三重编码当无障碍措施，我们把它当「在 148×220 上唯一读得出来的信息结构」—— 出发点是尺寸，不是道德 |
| moollm / CARD-RENDERING.yml | 把卡面渲染写成声明式 YAML 契约（区域/字体/尺寸/约束），交给渲染器执行 | 我们是文档 + 代码两处，没有中间契约层。这条我们弱：docs/40 的「分区总表」快是 YAML 了，但没机器校验 |
| Picva 交易卡提示词 | 面向图像模型的整卡提示词：材质、印刷工艺、箔纸、边框风格 | 这是生成图片的 prompt，不是设计决策 prompt。我们不出图，不要它 |

卡牌类的关键交叉点：外部所有卡牌方案都建立在「有原画/有贴图」上；我们无位图，所以「材质」在外部是采样，在我们这里是用几何画出来。这是根本分野，不是取舍。

## 二、游戏手感（juice / game feel）

| 来源 | 做法 | 与我们的差异 |
|---|---|---|
| gamedev-skills / game-feel | 核心原理：一次命中 = 5~8 个微小响应在 ~100ms 内同时触发（声音/粒子/顿帧/闪白/击退/震屏/飘字）；两条铁律：①夸张要短暂并回到静止（juice 是瞬态不是新的静止态）②按事件重要性分档。流程：确认事件钩子存在 → 每事件挑 2~3 个通道 → 动作必须缓动不能线性 → 顿帧与震屏只给冲击 → 反馈不碰模拟层 → 按重要性分档 → 玩着看 | 几乎就是 docs/41 的骨架（接单三拍 120+240、stamp/seal、震动波形）。差异三：① 他们有「不要过度」的判据（juice crosses into noise），我们只在 docs/41 §4.1 写了出声预算；② 他们有粒子/震屏这类我们引擎禁用的通道（纯 CustomPainter、不许大范围模糊）；③ 他们明确「顿帧用 timeScale 不停逻辑」，我们 Flutter 侧 Ticker 驱动没有等价物 |
| Apple 向 game-feel | 通道到达率表：触觉只有拿手机的人感觉到、屏幕动效只有看屏幕的人、声音是整个房间；由此推出单人工具可靠触觉、房间向场景必须把签名时刻放房间级通道。另有稀有度梯度（tick < confirmed < success < complete < winner）、跨通道升级必须同阈值、单一所有者（一个事件只能一层代码发反馈，否则双震）、每个通道都要有无障碍叙事 | 这一篇最能补我们：① 10 条提案全部把「接单」写成最重的一击，但没有一条问「这一声是给谁的」—— 她是拟人角色、手机在宿主手里，所以触觉+声音同时成立；② 「跨通道升级同阈值」直接对应 #3 的 2400/1800 两个周期争议；③ 「单一所有者」正是 sfx.dart 里 boot / flip 空调用那类坑的制度性预防 |
| 同一仓的 feedback-audit.md | 事件×通道矩阵：逐事件填视觉动效/触觉/音频/判定色，规则是签名事件必须 ≥2 通道、房间向事件必须有房间级通道；🔴=签名事件零反馈或高潮复用常规图案、🟠=单通道、🟡=平淡、✅=达标。然后跑三条只读审计线（触觉+声音清单 / 动效清单 / 一致性与到达率），每条都要 file:line 证据，明确写「未找到」胜过沉默 | 最值得直接搬的一张表。我们这轮是 10 条提案 × 17 栏，从来没做过「现有组件的事件×通道矩阵」。做完会立刻发现：开牌屉 flip 无声音（真空调用）、edge 波形零引用、咬合还在用 choose[8] |
| juice 的量化铁律 | 一次交互 5~8 个通道、~100ms 窗口；夸张必须回静止 | 我们接单三拍是 360ms，比他们长 3.6 倍 —— 因为我们是「契约被抽走」不是「打中一刀」。这个差异要有意识保留，不能照搬 100ms |

## 三、声音设计

| 来源 | 做法 | 与我们的差异 |
|---|---|---|
| gamedev-skills / audio-design | 总线架构（Master ← Music/SFX/Ambience/UI/Voice）、用 dB 不用线性、留 headroom（-14~-16 LUFS）、ducking（旁链压缩）、自适应音乐（纵向分层+横向重排）、SFX 变体化（随机音高/音量 + 采样池）、在真实输出上听 | sfx.dart 已有池化 + 多 variant（rung_0..4 / detent_0..4），等价于他们的 SFX variation。我们缺：① 没有总线（只有一个全局 volume）② 没有 ducking（她说话时音效不降）③ 没有 LUFS 目标，只有「相对响度已在素材里叠好」这句口头约定 |
| Apple 向 sound-design.md | 最小套件：不要一事件一音效，4~6 个精修音效覆盖全应用（tick / buzzer / ding / reveal / fanfare）；格式用 .caf+PCM（压缩格式有解码延迟）；AVAudioPlayer 预加载一次不每次 new；AVAudioSession 的 category 是策略决定要写下来；经典错误=为了播一个音就激活新的 .playback session | 我们 96 件 wav + 19 个 key，远超最小套件。不一定是错（有 12 情绪逐字音），但要问：这 96 件里有多少是「一事件一音效」堆出来的？他们五档对应我们的 detent/stamp/seal/publish/impact —— 结构上是同一套稀有度梯度，只是我们把「咬合」拆成了 5 个变体 |
| 我们现状（来自考据） | detent_0..4 28ms / stamp / seal 1.26s / rank_0..6 / rung_0..4 / deal_0..4 / play(key, variant:) 显式变体 / _longHold 防腰斩 / 12 槽池化 / 1200ms 看门狗 | 这套工程实现比外部 prompt 写的要硬：他们写「要变体化」，我们已经有变体 + 长音上界 + 丢弃计数。差异是我们反过来了 —— 实现领先于文档 |

## 四、触觉

| 来源 | 做法 | 与我们的差异 |
|---|---|---|
| haptic-design.md | 语义词表架构：enum HapticEvent { start, correct, pass, reveal, timerPulse, timerUrgent, stop, roundEnd, winner }，游戏代码只说「意义」不说「图案」；一个中央 service 独占引擎；API 选择表（.sensoryFeedback 够用就够用，≥4 个语义事件就该上 Core Haptics）；工程细节：懒启动、能力门禁一次、处理 stopped/reset、后台停引擎、注入为可选 seam | 直接命中我们已发现的问题：Haptics.pattern 不传 intensities，iOS 会把偶数位全补成震、Android 把首位当等待 —— 根因就是我们把「波形数组」当成了语义层。按他们的架构，「意义→图案」那层应该显式带 intensity，而不是把数组直接丢给插件 |
| 词表 vs 我们的 patterns 表 | 他们 9 个语义事件 | 我们 20 条波形，卡牌相关 4 条（stamp/deal/flip/edge），但咬合还在用 choose[8]、edge 零引用 —— 说明我们的表是「原型时期照搬的波形集合」，不是「按语义整理过的词表」 |

## 五、动效

| 来源 | 做法 | 与我们的差异 |
|---|---|---|
| motion-system SKILL | 时长令牌 6 档（instant 50 / fast 100 / normal 200 / moderate 300 / slow 400 / deliberate 600）；缓动词汇（standard / decelerate=进场 / accelerate=退场 / spring / linear 只用于循环）；编排规则：相关元素 stagger 30~50ms、同语义组同时长同缓动、stagger 序列总时长 ≤500ms、方向一致；reduced-motion 在系统层处理（禁用位移缩放旋转、替换为透明度、保留传达状态的动画、令牌级 0ms 覆盖） | design/tokens.dart 的 Motion 分四层共 19 个常量，但只有 7 个被引用。他们的「6 档、不超过用例数」正好说明我们 19 个太多；还有两条我们没有：① stagger 总量 ≤500ms（我们 V13 入场编排 760ms，超了）② reduced-motion 令牌级覆盖（我们是逐组件 if，不是 token 覆盖） |
| LottieFiles/motion-design-skill | 把迪士尼 12 原则适配到 UI（timing/easing/choreography） | 我们文档零星引用了 squash/stretch、过冲 1.08，但没有「12 原则」这种可对照清单。这条不必需（我们不做插画动画） |

## 六、横向拼起来看：我们缺什么

| 能力 | 外部共识 | 我们现状 | 缺口 |
|---|---|---|---|
| 事件×通道矩阵 | Apple game-feel 核心工具，逐事件 × 视觉/触觉/音频/判定 | 从未做过 | 最该补，能一次性发现 flip 无声、edge 死代码、咬合用错波形 |
| 通道到达率 | 触觉=持有人 / 声音=全屋 / 动效=看屏幕的人 | 默认手机在宿主手里 | 已隐含成立，但要写进文档，否则以后加平板/共享场景会翻车 |
| 稀有度梯度跨通道一致 | tick < confirmed < success < complete < winner，五通道同阈值 | 有梯度（detent < stamp < seal），但没有一张表列出五通道的同一档位 | 中 |
| 单一所有者 | 一个事件只能一层发反馈 | boot / flip 空调用说明根本没有所有者制度 | 该补，成本极低（一张事件→owner 表） |
| 最小音效套件 | 4~6 个精修音效覆盖全应用 | 96 件 | 不是缺口，是反过来：实现过剩、文档落后 |
| 时长令牌精简 | 6 档、不超过用例数 | 19 个常量、7 个被引用 | 该收敛 |
| stagger 总量上限 | ≤500ms | V13 入场 760ms | 要么承认超标、要么拆 |
| reduced-motion 令牌化 | 系统层 0ms 覆盖 | 逐组件 if | 该补 |
| 语义化触觉词表 | 意义→图案，中央 service 独占 | patterns 表 + 直接丢数组给插件 | 该补（正是 intensities bug 的根因） |
| 声明式卡面契约 | YAML/JSON 描述区域与约束 | 文档表 + 代码两处 | 可选，机器可校验才值得做 |

## 七、一句话结论

- 卡牌：外部的功夫在图层与材质采样，我们的功夫在几何与内缩顺序；他们是「把画分层」，我们是「把边分数」。
- 手感：外部的功夫在瞬时夸张（100ms 内 5~8 通道），我们的功夫在契约感（360ms 三拍）；不是谁对，是我们做的是「她被抽走一张委托」不是「打中一刀」。
- 声音：外部讲最小套件 + 混音总线，我们素材过剩、总线缺失。
- 触觉：外部讲语义词表 + 中央 service，我们是波形数组直塞插件 —— 而这正是 intensities bug 的根因。
- 动效：外部讲 6 档令牌 + stagger ≤500ms + reduced-motion 令牌化，我们 19 个常量只有 7 个在用、入场 760ms 超标。
- 真正只有我们有的：把「动效/声音/触觉三者自洽」当成提案的硬栏位（第 12/13 栏 + 自检第 5 条）。外部全部把这三样放在实现阶段的独立 skill 里，没有人在「选方向」这一步就要求它们互相自洽。

# V6 · 顶部节点面板 + 面板页 重设计（frontend-design）

> 起因：用户对比「图1 待执行顶部面板」与「图2 主线时间轴」，指出风格割裂。
> 结论：以主线时间轴（V5 冷光神殿）为唯一视觉基准，把两个组件补完到同一套语言。
> 代码位置：`prototype/app/index.html` —— `<style>` 末尾 `V6 · 冷光神殿 · 补完` 层 + `UI.nodeBody()` / `UI.radar()` / `UI.inv()`。
> 本文是规格与验证留痕；视觉基准仍以 `.stitch/DESIGN.md` 为准（本文只补 V6 组件级规格）。

## 0. 问题诊断（改前实测）

| 组件 | 实测问题 |
|---|---|
| 顶部节点面板 · 待执行（`#nodeSheet`） | ① 「要求」= 标题原文，同一句话在屏上出现两次；② 内容只占 480px 中的约 200px，CTA 之下约 280px 纯空；③ 只有 `.nplab`（9px 灰）＋正文两级，没有信息层级，读起来像设置表单；④ 难度印只有 30px、半透明、没有重量；⑤ 与主线时间轴零呼应（没有环号、没有轴线、没有进度），关掉面板就不知道自己在链条的哪一环；⑥ 主 CTA 用 V5 的透明青 ghost 样式，凹槽处出现"内嵌亮矩形"的视觉故障，看起来像浏览器默认按钮 |
| 面板页（`#pg-panel`） | ① `HOST STATUS` 孤立小标签 + 胶囊 LV + 称号 + 一行 meta，头部没有骨架；② 「累计完成」取主线已完成环数（0），与宿主的生涯完成数（S.done=6）自相矛盾；③ 雷达 230×210 的盒子 + 缩到 18% 的数据多边形，六维全是小三角，读不出形状；④ 观测结论是一坨 13px 正文卡；⑤ 道具栏＝两个等宽卡片；⑥ 商店＝两个等宽大卡 + 两个全宽亮青按钮，是全页最响的东西，但它是次要动作；⑦ 末节「未竟之志」标题贴着底栏，像被裁掉 |

## 1. 设计概念

- **顶部节点面板 = 从书脊垂下的一张系统委托单（WORK ORDER）**。它不是弹出表单，而是主线时间轴的一次"下拽投影"：上面挂着它在链条里的编号，下面把书脊横过来变成一根定位轨。
- **面板页 = 宿主档案（HOST DOSSIER）**。不是卡片堆，而是仪表读数台：读数条 → 六维阵列 → 系统日志 → 装备槽 → 兑换台 → 封存档案。

语言铁律（沿用 V5）：圆角 ≤2px；chrome 只用电光青，稀有度色只做数据色；信息靠**发丝线、点线引导线、光刻刻度**分层，不靠辉光堆叠；面板是"投影仪表"不是气泡卡。

## 2. 顶部节点面板规格（`#nodeSheet`）

结构自上而下（高度仍为 480px ≈ 屏高 60%，`#nodeBody` 为唯一滚动容器）：

1. **抓手** `.nsgrab` 36×3 发丝（点按即关；遮罩空白处也可关）
2. **锚定行** `.nsindex`：`RING nn / NN`（Rajdhani 14px，用该环稀有度色 + 同色渐变发丝）— 右侧 `主线「目标名」`（mono 8.5px）
3. **单头** `.nshead`：
   - 难度印 `.nseal2`：46×46，稀有度色 1.5px 边 + 外圈 5px 发丝副框，`rotate(-7deg)`，`box-shadow 0 0 22px -4px <稀有度色>`
   - 上方 `.nslab` 标签「要求 · REQUIREMENT」+ 渐隐发丝（**用标签承载"要求"语义，值就是标题，不再重复一句话**）
   - `.nstitle` 17.5px/600/1.42；下方 `.nsmeta`：稀有度色小点 + `E 级 · 心 维度 · 对应行动截图`（mono 9.5px）
4. **规格表** `.nsspec` / `.nsrow`（左标签 8.5px mono 0.2em ＋ **点线引导线** ＋ 右值）
   - 待执行：验证 / 维度 / 回报 / 限时
   - 已完成：时长 / 证据 / 结算 / 时段
   - 数字一律 Rajdhani 15px（`.nsrow .v b`），金币用 `b.g` 金色；中文不要塞进 `b`（会被 Rajdhani 回退成小字）
5. **证据槽** `.nsslots`：5 个虚线 4:3 槽 + `.nsslotcap`「证据槽 · 最多 5 张截图 + 文字备注」＋ `.nsfine` 验收条款「系统不查岗，只看截图。证据到位即核验。」
6. **执行态**：`.nslab.big`「已投入 · ELAPSED」+ `.nptime` 40px Rajdhani 实时计时 + 紧凑书脊证据轴（`#nodeBody .evl.spine{flex:1}` 吃满剩余高度，面板内不出现第二个滚动条）
7. **脚部** `.nsfoot`（`margin-top:auto` 吸底，`rgba(7,11,18,.97)` + 上发丝线）：
   - **书脊定位轨** `.nsrail`：横过来的书脊，5 个圆点 ＋ `01..05` mono 编号；走过=朱砂实心点／脚下=青呼吸点／未走=线框空心点；当前查看的那一环加一圈青色 outline（`.here`）
   - 待执行：`.nsctahint`（`ACCEPT · 接单` / `拔单即开始计时`）+ 实心青 CTA【接任务】（`.btn.solid`，全屏唯一最亮元素）
   - 执行中：`快照记录`(solid) / `提交任务`(ghost) / `认输`(.danger)
   - 手上有活时：`.nsbusy`「手上有活：先提交当前任务」替代 CTA
8. **已完成态**：无按钮（只读），规格表给出时长/证据/结算/时段 + 证据书脊

动作区用词固定：【快照记录】【提交任务】【认输】（与执行面板同款）。

## 3. 面板页规格（`#pg-panel`）

1. **档案头** `.dshead`
   - `.dslv` 56px 六边形等级牌（径向青渐变 + `::after` 外圈六边发丝）+ 下方 `LEVEL` 标签
   - `.dstamp` 称号压印（左 2px 青条 + 发丝边，不旋转，避免与难度印抢语义）
   - `.dsmeta` mono 一行：`主线「早起早睡」· 主题 心 · 周期 7 天`
   - **读数条** `.dsledger` 三格（发丝竖分隔）：`TOTAL · 完成` 青 / `COINS · 金币` 金 / `STREAK · 连击` 火橙；数值 Rajdhani 23px
     - 数据语义修正：完成数取 `S.done`（生涯累计），不再错用主线环数
   - **主线进度轨** `.dsmain`：`主线「目标」· 主题` + `n / N 环` + 2px 发光进度线
2. **六维 · ATTR ARRAY**
   - 雷达 250×232（`radar(){c:125,b:110,R:72}`）：4 层同心六边形（外层亮）＋ 6 条轴线 ＋ 每轴 3 枚垂直刻度 ＋ 数据多边形（径向填充，顶点白热小点）＋ 轴名（最高项 `.rax.hot` 青色）＋ **7.5s 旋转扫描扇面**（30° 半角，径向渐变从中心淡出，绘制在网格之上、数据多边形之下）
   - 量程：`mx = max(6, 最高值 × 1.25)`，最低留 12% —— 保证小数值也有形状，不再是"一团小三角"
   - 下方 `.attrrow` 六行：轴名 ＋ 3px 条形 ＋ （主线主题轴）`主线` 标 ＋ Rajdhani 数值；最高项整行青色
3. **系统观测** `.dslog`：左 2px 青条 + 渐变底，`SYSTEM LOG` 小标 + 观测结论正文；不再用卡片
4. **装备槽 · INVENTORY** `.slots`：3 槽（免死金牌=盾形描边 / 双倍卡=叠卡描边 / 空槽=虚线 + `+`）；每槽 图标 + mono 名 + Rajdhani 数量 + 单位
5. **兑换台 · EXCHANGE** `.exrow` 行式：图标框 ＋ 名称/说明 ＋ 金色价格 ＋ 描边按钮；**金币不足自动禁用并改文案为「金币不足」**（`UI.inv()` 内按 `S.coins` 判定）
6. **封存档案 · ARCHIVED** `.archrow`：`封存` 小印 + 划线标题 + 元信息，整体降透明；空态＝虚线框内 `> 无封存记录。宿主还没有放弃过任何目标——继续保持。`
7. `.pgtail` 22px 收尾，末节不再贴底栏

## 4. 兼容与回归

- **主按钮语言统一**：新增 `.btn.solid`（实心青 → 深青、深色字、`:disabled` 降透明），用于①顶部面板【接任务】【快照记录】②任务详情弹层【拔单执行】【提交任务】。原 V5 的透明 ghost 主按钮在凹槽裁角处会露出"内嵌亮矩形"，像浏览器默认按钮——这两处是"接单"动作的唯一入口，统一为全屏最亮元素
- 所有既有 ID 保留（`#radar #pLv #pTitle #pStats #pInsight #iMedal #iDouble #givenSlot #exMedal #exDouble`）与 `SYS.buy()` 调用不变
- 旧 `.shop/.sitem/.grid2/.stat` 类保留但仅在 `#pg-panel` 内隐藏（防其他页面复用出问题）
- 主线页 / 任务页 / 设置页 / 结算 / 绑定仪式未改动
- 未改动机制文档，本次纯视觉 + 一处数据语义修正（完成数取值）

## 6. 独立评审（只读对抗性评审）后的修补

改完先请了一个独立评审（只读、不看我的推理过程，只读截图 + 代码）打分。结论：**token 层一致、组件层仍不够**——并列出 16 条缺陷。采纳与拒绝如下。

### 已采纳（本轮已改）

| 问题 | 处理 |
|---|---|
| 旧列表规则 `.done{opacity:.45}` 漏到 `.node.done` / `.ev.done` | V6 层加 `.node.done,.ev.done{opacity:1}`。实测：回顾面板里「提交任务，等待验证」原本是全屏最暗的一行（lum 95 vs 邻居 192）；主线上"走过的那一环"比没走过的还淡，与 17 号文档「走过=实心发光轴+实色印章」相反 |
| 书脊定位轨的"未走"是实线，与主线的虚线暗轨语言相反 | 改成 `1px dashed`，与主线一致 |
| 面板页六维条形：有「主线」标的行被顶掉约 38px，右端参差 | 每行都预留固定 26px 标签列（无标时空占位），六条等高齐尾 |
| 执行中面板最上面一行只有发光点 + 时间、没有文字，像坏掉的一项 | `evlHtml(tl,true)` 补 `计时中` 文案 |
| 「手上有活」时脚部塌成一行文字，死区又回来了 | 脚部保持满高：`BUSY · 手上有活` + ghost 按钮【提交任务】（接固定动作词，不再只是提示） |
| 5 个虚线证据槽像真上传位（`UI.slots()` 才是真组件），是假可供性 | 文案改为「证据槽 0 / 5 · 接单后在【提交任务】时上传」，明确它是容量不是输入 |
| 动作词漂移：脚部同时出现 接单／拔单／接任务 | 统一为 `ACCEPT · 接任务` / `拔单即开始计时` |
| 我引入了全 app 最小的字号（7.5–8px 含中文） | 中文小标一律提到 8.5px（书脊编号、主线标、封存印、面板各类 key、装备槽名、SYSTEM LOG）；纯拉丁大写 8px（`LEVEL`）保留 |
| 回顾面板的结算数字取的是**名义**奖励，暴击/双倍卡翻倍后对不上 | `settle()` 落 `r.awarded={exp,coin}`，面板优先渲染实发值 |
| 回顾面板 4 行规格 + 证据轴挤压，书脊被硬切一半 | 删掉与证据轴重复的「时段」行（轴本身就带每个事件的时刻），书脊高度 96→117px；`.nsfoot::before` 加 24px 渐隐，截断处看得出"下面还有" |
| 无 `role="dialog"`／无 reduced-motion；抓手命中区只有 36×3 | `#nodeSheet` 加 `role="dialog" aria-modal="true" aria-label`；`.nsgrab::before` 把命中区扩到 143×35；`@media (prefers-reduced-motion:reduce)` 关掉雷达扫描扇面 |
| 面板页 `padding-top` 比其它页少 8px、`.pgtail` 与页面 78px 底距重复 | 统一 96px；`.pgtail` 22→14px |

### 未采纳（有意保留，附理由）

- **把"走过/提交"从朱砂红改成验收绿（`#34D399`）**：朱砂印是 V5 已定的世界规则（「系统是冷光，你是朱砂印」），完成=盖章必须暖、必须糙；改绿会把隐喻拆掉。认输用危险红、完成用朱砂，靠**位置与形状**区分（书脊顶/底 + 分类型节点），不靠色相。
- **雷达去掉数字/缩到 200×190**：雷达负责"形状"，下方 6 行负责"精确值 + 主线标"，是总览/明细的配对，不是重复；且它是面板页的主视觉，压缩会把它降级成配图。
- **`height:min(60dvh,480px)`**：原型是固定 390×800 的手机壳，`dvh` 取的是**浏览器**视口而不是手机壳高度，改了没有收益。这是 Flutter 移植时的正解（届时用 `constraints.maxHeight * .6`），已记在此处待办。
- **左右 20/16 内距改成对称**：左侧 2px 发光书脊占掉了视觉宽度，20/16 是光学平衡（可见内距 18/16），不是笔误。
- **证据轴的 `--wlk` 发光长度**：属于 V5 遗留的失效变量（`--wlk` 从未由 JS 赋值），改动会连带影响任务页执行面板，另开一轮处理。
- **连击数字改回青色**：连击属于火焰（橙色）的家族，改青会让读数条出现两个青色数字，反而更差。
- **字号地板提到 10–11px**：与 V5 已验收的密度（正文 8.5–9.5px mono 遍布主线页/委托板）冲突；本轮只清掉我自己引入的 7.5px。

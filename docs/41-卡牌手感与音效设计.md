## 0 · 一页速览

**这套牌摸起来该是什么感觉：像发牌员的手，不像网页的 tab。**

牌是被「发」到你面前的一叠实物 —— 侧着、缩着、压着，你伸手一拨，它就跟着走；
每过一格「嗒」一下（手指有、耳朵有、手上有一点点）；松手它不是"跳"到位置，是被弹簧带过去；
你点开它，它是被**抽出来**放在你面前；你接下它，它被**拿走**——那一下要有分量。

**听起来：低频归系统，高频归手指。**
系统替你做的事（发牌、落桌、压印、拿走、揭示稀有度）才有声音；
你自己做的事（拖、划、按）只给一格咬合与一下轻震。**手做的事不出声，系统做的事才出声。**

### 0.1 四条结论（下面每一节都在证明它们）

| # | 结论 | 证据 |
|---|---|---|
| 1 | **主线「接任务」是目前整条链路里唯一一次硬切** —— 没有压印、没有飞行、没有落点，一声 `seal` 之后整页直接换成执行面板 | `main_view.dart:817-821` 只 `Sfx.play('seal')` → `onAccept` → `main.dart:801` 的 `_moment = Moment.exec`（同一帧） |
| 2 | **牌桌的「档位咬合」有两处结构性浪费**：释放时会**多发一声随机的 `rung`**（音高不受控）；且 `rung` 是 70ms 的乐音，比 8ms 的震动慢一个数量级 | `card_table.dart:203-209`（`_onLeadChanged` 里 `Sfx.play('rung')` 不带 variant → 随机取 5 档）+ `card_table.dart:226` |
| 3 | **85 件资产里有 3 件是死的**（`boot` / `hold` / `rank` 兜底），其中 `Sfx.play('boot')` **每次唤醒都在空调用** —— `table` 里没有这个 key，`_pick` 返回 null，静默返回，连 `failCount` 都不加 | `sfx.dart:46-92` 的 key 集合不含 `boot`；`main.dart:2833` 却在调它 |
| 4 | **仓库自己的「过冲 ≤1.08」硬纪律被 6 处 `Curves.easeOutBack` 违反**（实测峰值 **1.0869**） | `Motion.maxOvershoot = 1.08`（`tokens.dart:146`）vs `main_view.dart:1461`、`plate.dart:1189`、`item_drawer.dart:75`、`result_panel.dart:219/839`、`exec_panel.dart:1085` |

### 0.2 最值得先做的一条

> **把「接任务」做成三拍：压印 120ms → 卡被抽走 240ms → 才切页。合计 360ms。**
> 因为它同时是**这一整套牌唯一的情绪结算点**，而且它是**局部改动**：只动 `main_view.dart` 的 `_drawerCta`，
> 外加一个 360ms 的取走覆盖层 + 一朵光痕。不需要新页面、不需要新状态机、不碰 `main.dart` 的时刻表。
> 详见 §3.7 —— 那是本文档唯一一条「做完了立刻能感觉到不同的」改动。

## 2 · 目标手感：五条判据（可逐条答是/否）

1. **摸得到因果**：手指压下去的那一刻（0ms）牌就变形；松开那一刻（同一帧）它开始走向落点。没有任何"等动画播完"。
2. **看得见惯性**：轻甩 1.9 格、重甩 3.8 格、到头有橡皮筋；松手不是跳，是被弹簧接住（速度交接，无接缝）。
3. **听得见层级**：轻声的（咬合）和重声的（压印）在**响度上差 ≥15dB**，闭着眼能听出「这是选了一下」还是「这是接下了」。
4. **稀有度有仪式**：S 级单子揭晓比 F 级长 **4 倍以上**，且长在「停一拍」而不是「加更多动画」。
5. **打断永远有效**：任何时刻点一下，0ms 响应，下一个 tick 落终态。

### 3.1 牌扇入场（「发牌」）

**原则**：入场**不锁输入**、**不加过冲**（`card_table.dart:20-21` 已经写对了）。要补的是「发」的**物理感**与**一声落地**。

| 拍 | 时间 | 变换 | 曲线 | 音 | 震 | reduce |
|---|---|---|---|---|---|---|
| 0 | +0ms | 领位牌：`scale .94→1`、`y −10→0`、`op .0→1` | `kEnterCurve`(.23,1,.32,1) | `deal_0` | `deal [4]` | 仅 `op` 160ms |
| 2 | +26ms | 第 2 张起，逐张 | 同上 | — | — | 同帧直接到 1 |
| n | +(n−1)×stagger | 每张错峰，**stagger = min(26, 80/(n−1))** | 同上 | 仅**末张** `deal_4` | `deal [4]` | — |
| end | +280ms | 全部就位，无过冲 | — | — | — | 160ms |

**为什么只有 2 声**（不是逐张）：
- 心理学上「先入为主效应」：相隔 **<20ms** 的两声会被听成一个；n=8 时 stagger 只有 11.4ms → 逐张出声 = 一片糊。
- 出声预算（§4.1）：一次发牌 ≤2 声。

**页级编排**（`main_view.dart` 760ms 那段）保持不变，只把页面级的「牌扇整块 8px 落下 + .94→1」视为**发牌的第一张**，
即 `fanT` 的 120ms 起点就是本表的 0 点。

**新增令牌**

~~~dart
static const int dealMs = 200;        // 单张旅行（= 现 kEnterMs）
static const int dealBudgetMs = 280;  // 整段上限（= 现 kEnterBudgetMs）
static const int dealStaggerMs = 26;  // 逐张错峰上限（牌多自动收紧，逻辑不变）
~~~

### 3.2 拖拽跟手（含橡皮筋）

**原则**：1:1 跟手、只走 `Transform`、可中断、速度交接 —— 现有实现已全部达标（`rail_base.dart:148-153`）。
本方案**不动机械**，只补两件事：**方向提示的力度**与**越界的触觉**。

| 拍 | 时间 | 变换 | 音 | 震 | reduce |
|---|---|---|---|---|---|
| 按下 | 0ms | 牌 `.97`（即按即缩，无补间） | — | `tap [8]`（仅非拖拽的普通点按） | 压暗 `.86` |
| 拖动中 | 每帧 | `p = lead − dx/stride`；整桌 `rotate(−frac×.035)`；每张 `rotate(a×5°)`；对角高光 `dragPhase = −frac×2` | — | — | 全部归零，只留位置 |
| 越界 | 连续 | `shownDx = sign × rubberBand(|dx|, W, .55)` | — | **新增 `edge [6]`**：越过边界的**第一下**（一次性，不是每帧） | 不震 |
| 松手 | 0ms | 弹簧 k120/ζ.9 从当前值 + 手指速度出发 | — | `land [18]`（若换了领位） | `dx = 0` 直接落位 |

**橡皮筋的实测响应**（`rubberBand(over, W=390, c=.55)` 的真实换算；430 宽屏差异 <0.3%，跟手率不变）：

| 越界 | 跟手量 | 跟手率 |
|---|---|---|
| 20px | 10.7px | 53% |
| 50px | 25.7px | 51% |
| 100px | 48.2px | 48% |
| 200px | 85.8px | 43% |
| 400px | 140.7px | 35% |

> 这组数是对的：**越界越深、跟得越少**（Apple §9 的"有回应，但到头了"）。不需要调。

**要改的一处**：越界目前**完全没有触觉**。手指已经推到头了，牌还在跟 —— 玩家唯一的线索是视觉。
建议在**首次越界**加一次 `Haptics.buzz('edge')`（`[6]`），**整段手势只震一次**，松开时重置。
这声「到头了」比视觉更早被感知。

### 3.3 档位咬合（每过一格的那一下）

**现状判定：不够，而且有一处是错的。**

| 问题 | 证据 | 后果 |
|---|---|---|
| ① 乐音太"长" | `rung` 70ms 方波（`gen_sfx.mjs:316`），而震动只有 8ms | 手指 8ms 就结束了，耳朵还在响 70ms → **"音画不同步"的轻微滞后感** |
| ② 释放时**多发一声随机 `rung`** | `_onLeadChanged` 调 `Sfx.play('rung')` **不带 variant**（`card_table.dart:204`）→ `_pick` 随机取 5 档之一 | 最后落定那一下会听到**音高随机**的一声（可能是低音，破坏"往右走高"的阶梯感） |
| ③ 音高阶梯只有 5 档、跨度 1.74× | 300→522Hz | 一段 10 张的牌扇，音高来回循环 2 次，听不出"走到第几张" |
| ④ 无噪声瞬态 | 纯方波 | 手机小喇叭上"塑料感"，不像卡牌卡进档位 |

**改法：新增专用 `detent_0..4`（不是复用 `rung`）**

~~~js
// tools/audio/gen_sfx.mjs 的 manifest 里（放在 rung 组之后）
// 档位咬合：一个 18ms 的高通噪声瞬态（"卡进去"）+ 一个 12ms 的方波 click（音高阶梯）
// 总长 28ms —— 与 8ms 震动同一个数量级，不再滞后。
for (let x = 0; x < 5; x++) {
  const f = 1400 * Math.pow(2, x / 4);        // 1400 → 2800Hz，一个八度 / 4 格
  add(`detent_${x}`, 44100, () => [
    N({ f: 3200, q: 2.5, dur: 0.018, vol: 0.05, a: 0.0005 }),      // 起音 0.5ms —— 要"咔"不要"呼"
    T({ f, dur: 0.012, vol: 0.018, type: 'square', lp: 6000 }),
  ]);
}
~~~

**实测（本机烘焙，seed=1，`inspect_wav.mjs` 全项通过）**

| 文件 | 时长 | peak | dBFS | <500Hz 能量占比 |
|---|---|---|---|---|
| `detent_0` | 0.028s | 0.0208 | −33.7 | 0.1% |
| `detent_1` | 0.028s | 0.0196 | −34.2 | — |
| `detent_2` | 0.028s | 0.0225 | −33.0 | — |
| `detent_3` | 0.028s | 0.0220 | −33.2 | — |
| `detent_4` | 0.028s | 0.0212 | −33.5 | — |

> 为什么 ≤−33dBFS 是对的：它是全场最高频的音（每 104px 一发），必须**响度在垫底那一档**，但峰值要过 −36dBFS 才在手机喇叭上听得清。这组数正好落在两者之间。

**时间轴（一格）**

| 拍 | 时间 | 视觉 | 音 | 震 | reduce |
|---|---|---|---|---|---|
| 跨格 | +0ms | 新领位：扫光 520ms 重播、外辉 200ms 淡入、牌面 `.97→1` | `detent_<d>`，`d = 跨过第几格 mod 5` | `choose [8]`（同一帧） | 只换位置，不响不震 |

### 3.4 落定（压印 1.02）

**现状**：`seal`(1.26s, −11.6dBFS) + `Haptics.buzz('seal')` [30,40,60] + scale 1.02 + 干亮闪 16%。
问题：**落定太"响"了**。`seal` 是全场第二重的音（仅次于 `impact`），却用在"我把这一张选定了"这种**高频**动作上。
一块牌桌 8 张牌，来回选 10 次 = 10 次 1.26s 的钤印声叠加 → 会吵（§4.1 正是为此）。

**改法**：落定拆成「轻落定」与「重接单」两档（见 §3.7）。落定本身降级为新增 `stamp`。

| 拍 | 时间 | 变换 | 曲线 | 音 | 震 | reduce |
|---|---|---|---|---|---|---|
| 0 | +0ms | `scale 1 → 1.02`（**只在这一张上**，其余不重绘） | `kOut` | **`stamp`**（0.29s, −16.3dBFS） | **`stamp [12, 10, 20]`** | 无缩放，只压印 |
| 1 | +0→+70ms | 亮闪 16% 线性衰减到 0 | 线性 | — | — | 亮闪砍半 |
| 2 | +70→+140ms | `scale 1.02 → 1` | `kOut` | — | — | — |
| 3 | +140ms | 结束，解锁 | — | — | — | 0ms |

**为什么 1.02 而不是 1.08**：1.02 是**压下去**（press-in），不是弹出来。过冲只属于"甩出来的东西"（`card_table.dart:22` 已经写对了）。
但 200ms 对一次点击偏长 —— **建议 140ms**（`Motion.respondMs = 140`，正好用现成令牌，不新增）。

**新增音效 `stamp`**

~~~js
add('stamp', 22050, () => [

  T({ f: 523.3, dur: 0.28, vol: 0.022, a: 0.003 }),        // C5 一声很轻的确认音

实测：0.290s / peak 0.153 / **−16.3dBFS** / 95.8% 能量 <500Hz。

### 3.7 接任务压印（**本文档的重点**）

**现状（必须先纠正任务书里的一句）**：
「接任务 = `seal` + 1.02 缩放」这个描述**只对补给/称号/证据成立**（`CardTable._commit` 的 `tapLeadAlways == false` 分支）。
**主线牌屉这条路上根本没有压印** —— `card_table.dart:245-251` 在 `tapLeadAlways = true` 时直接 `return`，
压印只在 `_commit` 的默认分支里。而主线的接单走 `main_view.dart:817-821`：

~~~
按下 → Sfx.play('seal') + Haptics.buzz('seal') → onAccept(i)
     → main.dart:_acceptPlanTask → _beginExec → setState(_moment = Moment.exec)   ← 同一帧
~~~

**这一帧，牌屉消失、牌扇消失、整页换成执行面板。** 用户心理上"我接了一张牌"，得到的反馈是"页面跳了"。
这是整套卡牌的**情绪结算点**，也是目前唯一一次硬切。

| 拍 | 时间 | 变换 | 曲线 | 音 | 震 | reduce |
|---|---|---|---|---|---|---|
| 0 · 压印 | +0ms | CTA 按下 `.96`；被判定的那张牌 **`scale 1 → 1.04 → 1.02`**、牌面叠 16% 白闪 | `kPop` | **`press`**（0.53s, −11.2dBFS） | **`stamp [12,10,20]`** | 只到 1.02，无闪 |
| 1 · 定格 | +120ms | 牌停在 1.02，白闪开始衰减；**牌屉 scrim 深到 .40**（"暗场"） | — | — | — | 0ms 落终态 |
| 2 · 抽走 | +120→+360ms | 牌 `1.02 → .62`、`y −18px`、`op 1→0`；同时从牌心飞出一道**光痕**到屏幕顶部计时 chip（240ms） | `kOut` | — | `land [18]`（落地那一下跟着光痕到点） | 直接落终点 |
| 3 · 交棒 | +360ms | 调用 `onAccept(i)` → 才切执行面板 | — | — | — | 同帧 |

**为什么 360ms**：`Motion.takeTotalMs = 120 + 240`。比牌屉开（420）短、比落定（140）长 ——
正好在"看得清"与"不烦人"之间；再长（≥500ms）就会开始觉得"卡"。
**注意：这 360ms 是整套牌唯一的"非响应"窗口，它必须可跳过** —— 任何点击都直接落终态（跳过规则见 §6.5，与稀有度仪式共用同一套）。

**这两声是「重的」**（`press` −11.2dBFS ≈ `seal` −11.6dBFS，但只有 **0.53s** 而不是 1.26s）：
短促、低频、一下就结束，正好是「东西被拿走」而不是「仪式完成」。

**新增音效 `press`**

~~~js
add('press', 22050, () => [
  T({ f: 90, f2: 42, dur: 0.38, vol: 0.3, a: 0.002 }),                 // 38ms 的亚低频冲击（"拿起来"的重量）
  N({ type: 'lowpass', f: 1600, f2: 300, dur: 0.2, vol: 0.12, a: 0.001 }), // 纸面被捏住的摩擦
  ...chord([293.7, 440, 587.3], { type: 'triangle', dur: 0.5, vol: 0.03, spread: 0.012 }), // D 大三和弦（"确认"）
  T({ f: 2093, dur: 0.18, vol: 0.02, at: 0.03 }),                      // 一声很轻的高光
]);
~~~

实测：0.534s / peak 0.274 / **−11.2dBFS** / **95.1% 能量 <500Hz**（低频，靠手机腔体共鸣能出来）。

**落地改动只有一处文件**：`main_view.dart` 的 `_drawerCta` ——
把 `onAccept!(i)` 包进一个 360ms 的取走覆盖层（`Stack` 上叠一层，`IgnorePointer` 关掉牌屉本体），
`whenComplete` 再调 `onAccept`。**`main.dart` 一行不用改**（这是这条建议最值钱的地方）。

> 反过来，「补给 / 称号 / 证据」那三张桌子的 `_commit` 压印**保持不变**（那是即时购买，不是"拿走"，语义不同）。

### 3.9 五态各自「待机时」有没有微动效？

现状：**只有执行中有**（光包 1.6s）。其余四态全部静止。

| 状态 | 待机微动效 | 周期 | 实现约束 | reduce |
|---|---|---|---|---|
| **待发布** `sealed` | 虚线**极慢**流动（`dashOffset` 0→−8px） | **2400ms**（= `heartMs`） | `CustomPainter` 里改一个 `phase`，15fps 重绘 | 不流动 |
| **可接** `open` | 状态线亮度随心跳呼吸（`α .45 ↔ .58`）+ 领位外辉跟同一相位 | **2400ms** | **复用同一个 `_run` 相位**，不新开 ticker | 静态 α .45 |
| **执行中** `active` | 光包沿 2px 线走圈（**已有**） | 1600ms（M-09） | 现有 15fps ticker | 不画（`progress < 0`） |
| **已完成** `done` | **无循环**（金线静止）；只有一次性的压印 280ms | — | — | 已满足 |
| **已放弃** `abandoned` | **无**（整张压暗本身就是终态语言） | — | — | 已满足 |

**「同屏 ≤2 个可感知循环」的核对**：牌桌页同屏 = 她（Live2D）+ 心跳（2400ms）+ 光包（1600ms）。
光包与心跳的**公共周期是 LCM(1600, 2400) = 4800ms** —— 两者每 4.8s 对齐一次，不会出现"越走越散"的错拍。
所以**第三条循环可以留**，但**不能再加第四条**：这就是为什么「待发布」的虚线流动必须**并到 2400ms 心跳相位**上，
而不是另起一个周期。

### 3.11 reduced-motion 统一纪律（硬约束）

**每一拍的降级必须是「落终态」，不是「快一点播完」。** 逐条：

| 拍 | reduce 下的行为 |
|---|---|
| 发牌 | **不挂任何入场动画**；`op` 0→1 用 160ms 交叉淡化（`card_table.dart:189-193` 现有做法保留），终点即终态 |
| 拖拽 | 位置仍然跟手（那是**直接操作**，不是装饰，不能关）；倾角/高光/倾斜全部归零 |
| 咬合 | 换位置 + 换音（音效保留，视觉脉冲去掉） |
| 落定 | 不缩放，只压印 + 音 |
| 开/关牌屉 | scrim 直接 .22，牌屉直接到位（**不播位移**） |
| 接任务 | 0ms 落"已拿走"终态，然后照常切页；音/震保留（声音不是动效） |
| 状态变化 | 直接换终态样式 |
| 揭示 | **直接终态**：档位字母/颜色/奖励全部已就位，只出一声短的 |
| 待机微动 | 全部静止（虚线不流、不呼吸、不跑光包） |

**代码口径**：一律 `railReduceMotion(context)`（`rail_base.dart:72`），新组件不许自己读 `MediaQuery`。

## 4 · 音效设计

### 4.1 出声预算（**先定这个，否则一定会吵**）

三条铁律：

1. **手做的事不出声，系统做的事才出声。** 手指下的牌已经在跟手（直接操作），声音是多余的；
   系统替你做的（发牌、落桌、压印、拿走、结算）才需要一声"我做了"。
2. **一次交互 ≤ 2 声。** 超过 2 声就要问"哪一声是因果、哪些是装饰"。
3. **响度分三层，层间差 ≥15dB。** 摸（−33）/ 做（−27~−16）/ 结算（−11~−9）。

| 场景 | 出声上限 | 最小间隔 | 具体分配 |
|---|---|---|---|
| 一次普通点按（按钮/菜单/关闭） | **1** | — | `tap` |
| 一次落定（选牌） | **1** | — | `stamp` |
| 一次开/关牌屉 | **1** | — | `flip` / `sleeve` |
| 一次拖动（跨 n 格） | **≤ n 声，且总计 ≤6** | 120ms（跨格 <120ms 时**跳过这一发**） | `detent_*` |
| 一次发牌 | **2** | 200ms | `deal_0` + `deal_4` |
| 一次接任务 | **2** | — | `press` +（光痕落地）`land` |
| 一次稀有揭示 | 普通 1 / 稀有 2 / 传说 3 | 200ms | 见 §6 |
| 一次结算 | **≤9** | 55ms（`count` 例外，见下） | `impact` + `count`×≤6 + `crit` + `levelup` |
| 一次页面转场 | **1**（且**只有**大厅↔主线用） | — | `whoosh` |
| 全场每秒上限 | **8 发**（不含打字机音节） | — | 池子 12 槽 / 250ms 已有硬上限 |
| 打字机音节 | 独立通道 | 34ms | `syl_*`（走另一条语义，不计入上表） |

**明确的静音区（现在是响的，建议关掉）**

| 位置 | 现状 | 建议 |
|---|---|---|
| `main.dart:2757` 进度带收割 `count` | 与结算页的 `count` 只差几百毫秒 → 两声同源叠加 | **去掉**（结算页已经响过连续 6 发，回大厅再响一发是重复） |

### 5.3 iOS 的 Core Haptics 与 Android 的差异（**这里有真 bug，不只是"差异"**）

读完 `vibration 3.2.1` 的两端实现（`ios/.../VibrationPlugin.swift`、`android/.../Vibration.java`）后，有**四条**必须写下来：

**(1) 同一个 `pattern` 数组，两端解释不同 —— 首元素语义相反**

| 平台 | `[30, 40, 60]` 被解释成 | 结果 |
|---|---|---|
| iOS | 事件序列：`on 0–30`、静默 `30–70`、`on 70–130` | **震—停—震**（正确） |
| Android | `VibrationEffect.createWaveform(timings, …)`：**timings[0] 是"先等多久"** | **停 30—震 40—停 60**（错位一格，最后那一下丢失） |

→ **一行修法**：Android 侧调用时把 `0` 补在数组最前面：

~~~dart
// haptics.dart 的 pattern()
final List<int> p2 = defaultTargetPlatform == TargetPlatform.android
    ? <int>[0, ...p]      // Android 的 createWaveform 首元素是"等待"
    : p;
~~~

这会一次性修正**现有 16 条里所有多元素波形**（`boot` / `impact` / `crit` / `levelup` / `seal` / `rank`）的 Android 节奏。
**这是本文档里最便宜、影响面最大的一行。**

**(2) Android 上"轻重"只有长短，拿不到振幅**

`Vibration.java:18` 的 `vibrate(duration, amplitude)` 只在**单发**（`createOneShot`）路径里用 amplitude；
多元素 waveform 路径**没传 intensities** → 全部满幅。
而 iOS 侧 `getIntensities()` 会把 amplitude 摊成每段强度。

→ **设计含义**：在 Android 上**不要用振幅表达"重"**，用**时长与段数**表达（`stamp [12,10,20]` 42ms vs `detent [5]` 5ms —— 差 8 倍）。
如果将来要真正的轻重，得传 `intensities: [...]`（Android 8+ 且 `hasAmplitudeControl()`），但 iOS 与 Android 会各有一套写法，**本方案不做**。

**(3) iOS 的降级路径是"整机长震"，不是"没震"**

`VibrationPlugin.swift:302-307`：`supportsHaptics()` 为 false（老设备 / 模拟器）时调
`AudioServicesPlaySystemSound(kSystemSoundID_Vibrate)` —— 这是**一整下 ~400ms 的整机震动**，
与我们要的 5ms 咬合差了 80 倍。iPhone 15 Pro Max 走 Core Haptics 没问题，
但**旧机/模拟器上这 16 条波形会全部退化成同一个"嗡"**。

→ **设计含义**：不要在低端机上依赖震动传递"轻/重"的区分；音效必须独立承担完整语义。

**(4) Android 侧有一个值得记一笔的实现细节**

`Vibration.java` 里所有振动都带 `AudioAttributes.USAGE_ALARM` —— 意思是**静音/勿扰模式下也会震**。
对一个"自我提升 App"来说这大概是对的（用户静音也想被提醒），但要知道这是插件的硬编码，不是我们的选择。

## 6 · 稀有度揭示的仪式

### 6.1 三档定义

| 档 | 稀有度 | 时长 | 触发点 | 核心差异 |
|---|---|---|---|---|
| **普通** | F / E / D（i = 0–2） | **280ms** | `Plate._rankSettled` 之后 | 只是"亮一下"，不加层 |
| **稀有** | B / A（i = 4–5） | **600ms** | 同上 | **停一拍** + 环扫 + 数字滚 |
| **传说** | S（i = 6） | **1200ms** | 同上 | 暗场 → 蓄能 → **在 A 上停 560ms** → 白闪 → 箔层 |

> **关键设计**：三档的差别**不是"加更多动画"，而是"停得更久"** —— 杀戮尖塔的卡牌获得演出也是这个原理：
> 长在**节奏的空白**上，不是长在装饰上。

### 6.2 逐帧表（普通 · 280ms）

| ms | 视觉 | 音 | 震 | reduce |
|---|---|---|---|---|
| 0 | 牌面叠 6% 稀有度色亮帧 | `rank_0/1/2`（按档变调，**已有**） | — | 直落终态 |
| 0 | 骰子大字 `scale 1.9 → 1`（**已是现有 `rankLock` 的实现**，`plate.dart:1189`） | — | `rank`（仅 i≥5，**已有**） | 无缩放 |
| 70 | 亮帧衰减到 0 | — | — | — |
| 280 | 结束 | — | — | — |

> 普通档**不改任何东西** —— 现在就是对的（`_rankSettled` 的 `rank` 音 + `rankLock` 砸回 + flash）。

### 6.3 逐帧表（稀有 B/A · 600ms）

| ms | 视觉 | 音 | 震 | reduce |
|---|---|---|---|---|
| **−200** | **静默前置**：上一拍结束，什么都别响（仪式感来自"停顿"） | — | — | — |
| 0 | 稀有度色亮帧 13%（≥B 时 `onRankFx` 现在给的就是 .13） | `rank_4/5`（已有） | `rank [20,30,50]`（≥5） | 直落 |
| 0 | 牌面外圈：2px 稀有度色**环扫** 360° | — | — | 不画 |
| 120 | 档位字母 `scale 1.9→1`（`rankLock`）+ 一层 8% 白 | — | — | — |
| 200 | `reveal_1` 起（0.95s，−13.9dBFS） | 🆕 | — | 只在跳过时补 |
| 240 | 奖励行（EXP/金币）从 0.6 起 scale 到 1、数字 300ms count-up | — | — | 直接终值 |
| 480 | 环扫回收，只留一圈静止描边 | — | — | — |
| 600 | 结束 | — | — | — |

### 6.4 逐帧表（传说 S · 1200ms）

| ms | 视觉 | 音 | 震 | reduce |
|---|---|---|---|---|
| **−200** | 静默前置 | — | — | — |
| 0 | **暗场**：全屏 `#020610` α 0 → **.35**，其余元素压暗 | — | — | 不压 |
| 0 | 骰子四周的环开始**收拢**（r 从 1.4× 收到 1×） | `ritual_charge` 0.19s（−31.7dBFS，"充气"） | — | 跳过 |
| 200 | **锐利的一下**：白闪 16% / 180ms + 抖动 6px | `rank_6`（1.77s，**已有**） | `rank [20,30,50]` | 白闪砍半 |
| 200 | 骰子 `scale 2.2 → 1`（**比稀有档更大的起点**） | — | — | 直落 1 |
| **760** | **停一拍**：A 档已经停了 560ms（现有 `RankRollTimeline.dwellMs` 的 S 特例），这里不再加任何东西 | — | — | — |
| 760 | 箔层亮起：S 级全息箔 + 6k 噪声（`rank_6` 自带） | — | — | 不画箔 |
| 900 | `reveal_2` 起（1.27s，−13.0dBFS） | 🆕 | `impactLight [30]` | 只补一声 |
| 1000 | 暗场 α 从 .35 回 0（200ms） | — | — | 同帧回 0 |
| 1200 | 结束，落终态 | — | — | — |

**为什么 200→760 要停 560ms**：`plate_timeline.dart:59` 里 `if (target == 6 && i == 5) return 560;` ——
**原型本来就在 A 上多停一拍**。我们的仪式**必须尊重这个既有节拍**，不能另起一套。
这一停就是"传说感"的全部来源：全场安静 560ms 后才是 S。

### 6.5 如何打断（玩家点一下就跳过）

| 规则 | 实现 |
|---|---|
| **90ms 内不响应跳过** | `Motion.skipGuardMs = 90` —— 防住"揭晓那一帧本来就有一根手指在屏幕上"的误触（例如按住指纹的半途松手） |
| 90ms 后**任意点击 = 立即跳过** | 仪式窗口内挂一层 `Positioned.fill` + `GestureDetector(behavior: opaque)`；仪式结束（或被跳过）**立刻摘掉**，不许留在树里 |
| 跳过 = **落终态**，不是"快放" | 直接把 `AnimationController.value = 1`；档位字母 / 颜色 / 数值 / 印章全部写最终值；**不超过一帧** |
| 跳过之后**不再发新声** | 已起的那一发让它自然衰减（最长 1.27s），**不做硬 stop** —— `Sfx` 没有 stop API，加一个会引入平台差异；用一个 `int _ceremonyToken`，每次跳过 `++`，后续 `play` 校验令牌即可 |
| 跳过时的收尾动画 | `Motion.skipFadeMs = 120` 的交叉淡化（不是"啪"地切），其余全部瞬时 |
| **不打断的情况** | 应用切后台 / 页面销毁 → 直接释放控制器，不发回调（现有的 `_gen` 代际号模式，`plate.dart:86` 已有） |

### 6.6 贯穿性约束

- **仪式不锁输入**：跳过层本身就是输入层，所以"点一下就跳过"与"界面还能响应"是同一件事。
- **仪式不阻塞业务**：结算数据在仪式**开始前**就已经落库（`_flow.settle()` 在 `main.dart:1499` 已先行调用），
  仪式只是**播放**，中断不影响任何数值。这一条必须写进代码注释，否则将来一定会有人把 `await` 塞进数据链路。
- **reduce-motion**：三档全部**直接终态 + 单声短音**；暗场、箔层、环扫、抖动全部不画不播。

### 8.3 弹簧的实测

`Spring(k:120, ζ:.9)`（半隐式欧拉 + 1/120 子步）：

~~~
从 104px、初速 800px/s  → 峰值 113.7px（+9.3%），1.43s 才落到 |x|<1e-3
从 208px、初速 1500px/s → 峰值 225.3px（+8.3%），1.47s 静止
~~~

> 含义：松手后**视觉上 300–500ms 就"差不多到位"了，但数学上要 1.4s 才完全停**。
> 这就是为什么"咬合回声 90ms"必须与弹簧分开设计 —— 不能在弹簧还没停时又加一拍视觉反馈。

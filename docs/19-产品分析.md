## ① 产品缺点（诚实清单，按伤害排序）

### A1 · 新用户入口断裂：真新档不可达，绑定流被 demo 档吞掉 ⚠️ 最严重

**事实**：无存档冷启时 `_restore()` 的 fallback 是 **demo 老宿主档**（林深·LV7·半马 8 环主线已走 5 环·340 金币·全套道具，`main.dart:1728-1731`），且 `_wake()` 无条件进大厅（`main.dart:1715-1716`）——**全新安装的用户直接以「林深」的身份进大厅，开机屏写着「林深 · LV7」**（`main.dart:1205`），本轮升级的招牌「新用户绑定流+卡片式访谈+首目标 3 天」**对真新用户完全不可见**。唯一到达绑定仪式的路径是设置页「按住 2 秒重置」——而 `_wipe()` 的 fallback **同样是 demo 档**（`main.dart:1350-1353`）：走完绑定的"新用户"其实是 LV7、揣 340 金币的林深。`HostState.empty`（LV1 白板）在产品流程里**零引用**。这正是 CHECKLIST 里「访谈 5 卡」「HUD 7→10」的成因（lv7≥4 → 3+2 张卡；demo 经验近满 → 结算连升）。

**后果**：三层伤害。① 第一印象错乱：新用户被塞进别人的人生（别人的名字、别人的半马目标），小祥对「林深」的记忆全是假的；② 设计好的新客旅程（E/D/C 三天必胜、3 卡轻访谈、need 曲线起步）从未发生——**升级最核心的交付对新用户等于不存在**；③ 数值体系穿透：lv7 起步直接跳过前 5 级养成节奏，340 金币可立刻买空道具架。

**修法**（一句话）：无档冷启 fallback 改 `HostState.empty` + 检测未绑定时 `_wake()` 进 onboard（已绑定才进大厅）；wipe fallback 同改。工作量 **S**（两处 fallback + 一个分支），是全表性价比最高的一张卡。若团队有意保留「演示模式」，也应改成首启二选一（【先看看她的样子】→ demo 档 /【立即绑定】→ onboard），而不是让演示档冒充新用户。

### A2 · 第二目标闭环断裂——认真用户的生命周期只有 3 天主线

**事实**：全 App 只有一个目标生成器 `buildFirstGoal`（3 天 3 环 E/D/C，`goal_gen.dart:1081`）；docs/18 §2.1 设计的「3 天后再展开 5~8 环长链」**没有实现**（全文件无 full-chain builder）。主线走完（finale）后：队列不再补主线（rollDay 只在 `curRing>=0` 时重钉）、`换目标` 按钮只开聊天（`main.dart:1168`），而聊天**没有能落库换目标的工具**（见 A3）——排除 A1 的 wipe 路径后，用户**没有任何办法立第二条主线**。

**后果**：认真玩的用户第 4 天到达「叙事终点」：日常单还在发，但主线（本产品的灵魂：环、她头顶的目标、CLEAR·主线第 N 环）永久熄火。留存曲线在第 4~7 天必然断崖。

**修法**：finale 时弹「立下一条主线」（复用同一条访谈流，等级/金币保留）；聊天挂 `new_goal` 工具直接落库。工作量 M。

### A3 · Agent 工具注册表是死代码——「对话即操作」半成品

**事实**：6 个工具（get_status / swap_quest / adjust_plan / remember / recall / summarize_progress）在 `agent/tools.dart:295` 定义齐全、有测试，但 **`defaultAgentTools` 在全 App 零调用**（grep 仅定义处）；`ChatService.reply`（`chat_service.dart:63-106`）不向 LLM 传 tools——没有 function calling；聊天面板也没有无 LLM 的快捷 chip（docs/18 §2.5 承诺的保底形态）。CHECKLIST §5 的「换任务 ✅」实际是 D4 按钮（本地 retreat）+ 聊天场景注入（只影响话术）——**对话本身改不了任何状态**。

**后果**：宿主钦定的「agent 工具（查状态/换任务/调整计划）」用户侧不存在。对小祥说「帮我换个任务」，她只能嘴上答应。产品差异化卖点（AI 系统娘能替你操作 App）落空一半，且与 A2 叠加成死结：换目标入口开着、门后没有门。

**修法**：chat_service 加 tools 透传 + 工具执行回执气泡；聊天面板 3 个快捷 chip（无 Key 也能用）。工作量 M（registry 现成，纯接线）。

### A4 · 零提醒 / 零通知——习惯类 App 的生命线缺失

**事实**：pubspec 无任何通知依赖（`pubspec.yaml:9-22` 全量 7 个依赖）；无前台服务、无 exact alarm、无 local notification。所有循环（清晨钉单、rollDay、连击判定）都靠**用户自己打开 App** 才触发（CHECKLIST §3 的「次日补单」是 adb 改时钟模拟的；真实世界 = 用户不打开就没有第二天）。

**后果**：习惯养成的对手是遗忘。竞品 Forest/Streaks 的核心触达全是通知（睡前提醒、连击保卫战）。本产品的「早睡早起」目标不会在 23:00 提醒任何人——**目标类型与提醒时机天然成对**（sleep→睡前、run→傍晚、exam→自选时段），这是白白放掉的留存杠杆。连击机制没有通知保卫，等于惩罚不打开 App 的人，进一步把人推走。

**修法**：`flutter_local_notifications`（Android 12 走 `SCHEDULE_EXACT_ALARM` 权限流），按目标类型配 1 个钉单提醒 + 1 个截止前提醒，设置页可关。工作量 M。

### A5 · 内容耗尽：日常池约 9~18 天见底，主线池一次用完

**事实**（数过）：日常模板全量 51 条 = 通用池 14（`goal_gen.dart:911-962`）+ 十类专属 37（平均 ~4 条/类，gen 类为 0）；单用户可见池 = 本类 ~4 + 通用 14 ≈ **18 条**。每日 1~2 单 → **9~18 天内必然开始重样**；等级提档（lv4/lv8）只改档位不改题面。主线环：每类 `firstRings` 只有 3 环（32 个 RingSpec / 10 类），无 5~8 环长链（同 A2）。LLM **没有接进任务生成**——只用在文案/聊天/视觉，任务本体 100% 模板。

**后果**：第 2~3 周「她今天派的还是那几张」的重复感先于激励疲劳到来；毒舌文案是 LLM 的、可以不重样，但**任务内容**是死的——用户很快发现「系统娘嘴上新、手上一套旧单」。

**修法**（分层）：① 短期——模板参数化（时长/组数/地点词随机变体，S）；② 中期——`gen_daily` LLM 工具（按目标+记忆生成新日常，模板兜底，M）；③ 长链目标 5~8 环（与 A2 同一张卡，M）。

### A6 · 数据回顾缺失：200 条历史躺着，用户看不见自己的成长曲线

**事实**：`history` 满 200 条存在存档里（quest_flow 结算逐单写入）；但 UI 只有档案页 4 个静态计数（完成/暴击/认输/最长连击）+ 雷达快照（`sheet.dart`）；**没有周报、没有趋势线、没有六维前后对比**。本可做这件事的 `summarize_progress` 工具是死代码（A3）。

**后果**：习惯类产品的第二留存支柱是「回顾产生拥有感」（Streaks 的日历墙、Forest 的森林）。本产品的成长证明只有一条经验条和一个雷达快照——上周比这周强在哪？说不出。中期留存（第 3 周+）没有「舍不得删」的资产感。

**修法**：档案页加「近 7 天」小节：完成率环形 + 六维前后对比 + 一句 LLM 周评（copy provider 现成兜底）。工作量 M。

### A7 · 激励天花板：曲线后期拖、金币去处单一、称号 12 枚封顶

**事实**：`need(lv)=12+6lv`（`rewards.dart:36`）。日入经验约 2~8（1~2 日常 E~C + 偶发主线环）→ lv5→6 需 42 exp ≈ **1~3 周一级**；lv10 后 ≈ 1~2 月一级——前期节奏好（真新档 3~5 天升 lv2），后期升级感趋零。金币：日入 5~20，唯一去处 4 件道具（30~90 ◈，`items.dart`），道具只在「执行中」有用——金币会**无痛囤积贬值**。称号 12 枚（`titles.dart:15-26`），done15 之后长期无新目标（叠加 A2：finale 称号拿完就到头）。

**修法**：① 后期曲线分段（lv≥8 斜率减半，S）；② 金币新去处——Live2D 内容解锁（28 表情/64 动作里挑「表情包/待机池」做金币皮肤，与 3.3 差异位互相成就，M）；③ 称号扩展阶梯（done50/streak30…，S）。

### A8 · 单机无备份：清档即清零，换机即丢档

**事实**：全部状态在 SharedPreferences（save/v1 + settings/v1 + memory/v1 + chat/v1）+ 本地照片目录，无导出/导入，无云。wipe 是破坏性操作且（在 A2 修复前）是「立新目标」的唯一路径，误触成本极高。

**后果**：用户资产（等级/记忆/聊天史/照片）脆性大：丢手机=丢一切；换机=从零绑定。对「长期陪伴型」人设产品，这是信任问题不只是功能问题——小祥说「我记得你」，但换个手机她全忘了。

**修法**：先做**本地导出/导入**（单文件 JSON + 照片 zip，经系统分享/文件选择器，S~M）；云同步（P2，L，涉及账号体系决策）。

### A9 · LLM 依赖边界：无 Key 用户拿到「哑巴版灵魂」，且配置不热更

**事实**：产品最大卖点（AI 系统娘+视觉校验+记忆）依赖用户**自己去 DeepSeek 开平台、拿 API Key、粘进设置页**——首次启动没有任何引导（无 Key 时 fallback 5 句毒舌轮播，`chat_service.dart:29-35`）。遗留缺陷：设置页改 Key/BaseURL 后聊天与文案网关**不热更**（`_initAgent` 仅启动装配，CHECKLIST §5 观察项①）。成本面：单活跃日 ≈ 4 次文案（发布/结算×2）+ 数次聊天 + 每张照片一次视觉 ≈ 6~15 次调用，deepseek-flash 量级下**每人每月几分到几毛钱**——成本不是问题，**门槛才是**。

**后果**：绝大多数普通用户不会配 Key → 他们体验到的「小祥」= 5 句固定台词；「视觉校验」= 永远「未校验」。产品在无 Key 用户面前退化为「一个有漂亮立绘的习惯打卡器」——而这批用户恰恰是最大盘子。配了 Key 的用户获得完整灵魂，口碑割裂。

**修法**：① 首启「唤醒小祥」三步引导（注册→复制→粘贴→测试连接，S）；② 热更修复（S，CHECKLIST 已挂号）；③ 中期考虑官方代理 Key（成本可控但涉及计费决策，先不承诺）。

### A10 · 新手摩擦：访谈卡本身过关，真摩擦是「身份错位 + 下一步不明」

**事实**：访谈卡设计是过关的——lv1=3 张（每卡点一个 chip 即过，实测 45~90 秒）；lv2~3 加「投入时段」、lv4+ 再加「上次结果」（`goal_gen.dart:1044-1053`），梯度合理。真正的摩擦：① **A1 的身份错位**（新用户顶着林深的档案做访谈，答完题生成的却不是自己的起点）；② 绑定完成后只有一句见面礼横幅，「下一步按右下角接第一单」没有明示；③ 开机自检→绑定演出链路偏长且不可跳过。注意：CHECKLIST 实测的「5 卡」正是 lv7 demo 档（3+2）——A1 修复后新用户会看到更短的 3 卡，摩擦进一步降低。

**修法**：绑定收尾插话改为明确指引；开机演出加「点按跳过」。工作量 S（依附 A1 一起做）。

### A11 · 错误态/空态的产品完整性：达标项（点名表扬，不整改）

空队列「今日已清」拒绝进板（`main.dart:798`）、无 Key 视觉「未校验·未配置 Key」零等待、测试连接带服务器原因、断网聊天固定兜底句不卡 UI、拍照回流与坏档自愈——CHECKLIST §4 全绿。这块是当前版本的**强项**，无需动作。

## ③ 应用性：这东西给谁用、怎么被用、凭什么赢

### 3.1 目标用户画像

- **核心画像**：18~30 岁、中文网文/二次元文化浸泡者（看得懂「系统流」「绑定宿主」「S 级委托」这套叙事母题），有自我提升意愿但**讨厌严肃工具的说教感**——Forest 太幼稚、Notion 太上班。他们为「被毒舌系统娘管着」这件事本身付费（情感投射：鞭策+陪伴）。
- **次级画像**：AI 尝鲜者（愿意配 API Key、会安利「我的 AI 会记住我」）；被视觉包装（Live2D 少女+全息委托板）吸引的颜值党。
- **反画像（当前不该追）**：纯效率党（要数据导入导出/多端/日历集成）、青少年（API Key 门槛+网文语感门槛）、海外用户（文案/人设深度绑定中文语境）。

### 3.2 使用频次假设（产品节奏预算）

| 时点 | 场景 | App 内时长 | 触发 |
|---|---|---|---|
| 清晨首次打开 | 看新单、接主线环 | 1~2 min | 自主/（P0-4 后）通知 |
| 执行前 | 拔单确认时限证明方式 | <30 s | 自主 |
| 执行后 | 拍证据→提交→看结算演出 | 1~3 min | 自主 |
| 碎片时间 | 和小祥贫两句/查状态 | 1~5 min | 情感驱动 |
| **合计** | **2~4 次/天，日均 4~10 分钟** | | |

关键判断：低频短会话+高情感密度产品。约束：单次会话价值 30 秒内兑现（结算演出 ≤1.6s 已达标）；跨会话价值靠通知（缺失，P0-4）与回顾（缺失，P1-2）——两个缺口都在路线图上。

### 3.3 竞品差异位

| | Forest | Streaks/HabitTracker | Habitica | **system_panel** |

| 拟人陪伴 | 无 | 无 | 弱（NPC） | **强：LLM 系统娘+长期记忆+可操作 App 的 agent 工具（P0-3 后兑现）** |
| 打卡验证 | 专注时长 | 自觉 | 自觉 | **拍照+AI 视觉校验**（独一份） |

| 提醒 | ✅ | ✅ | ✅ | ❌ **（P0-4 补）** |

**差异位一句话**：唯一把「习惯养成」包进**网文系统流叙事 + 真人 AI 系统娘（有记忆、能替你操作）+ 证据校验**里的产品——竞品在做工具，本产品在做**关系**。短板恰好全是「工具基本面」（提醒/回顾/备份），正是路线图 P0/P1 的内容：**用人格留住心，用基本面留住手**。

### 3.4 一页结论（给决策者）

1. 当前版本是一个**完成度极高的 3 天体验**：绑定→访谈→首目标→打卡→结算→对话→记忆，全链路真机验证过。作为「第一印象版本」的工程质量合格且惊艳。
2. 但它有一个**一行的入口 bug 级产品缺陷**（A1：新用户看到的是 demo 林深）和一个**没有第二周的结构缺陷**（A2+A4+A5：无第二目标/无提醒/内容 9~18 天见底）。P0 五项合计约 4~5 人日，是全表性价比最高的投入——其中 P0-1 只要半天。
3. A3（工具死代码）是对宿主承诺的欠账，纯接线 M 量，建议与 P0-2 同批（`new_goal` 工具一起交付）。
4. 所有 P0/P1 均不推翻 docs/18 的架构——quest_flow/goal_gen/agent 分层把每条路线图项都落在「加文件/加工具」的轨道上，无返工风险。

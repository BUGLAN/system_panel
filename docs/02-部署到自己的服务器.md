# 02 · 部署到自己的服务器

> 服务端版（2026-11-21 起）：一个容器同时跑 API 和前端静态文件，SQLite 单文件 + 证据照片放在挂载卷 `/data`，前面用 Caddy 自动 HTTPS。
> 旧的 Cloudflare Pages 纯静态部署作废（git 历史里还在）。

## 0. 准备

- 一台 Linux 服务器（1 核 1G 足够自己 + 几个朋友用），装好 Docker 与 Docker Compose 插件
- 一个域名，A / AAAA 记录指向这台服务器；防火墙放行 80、443（TCP）与 443（UDP，HTTP/3 可选）
- （可选）一个 OpenAI 兼容的模型服务商：文本模型 + 视觉模型。服务端代为调用，不再要求服务商放行浏览器 CORS

## 1. 第一次部署

```bash
git clone <仓库地址> host-system && cd host-system
cp .env.example .env
```

编辑 `.env`（每个变量的说明都写在 `.env.example` 里），至少填：

| 变量 | 说明 |
|---|---|
| `APP_ORIGIN` | `https://你的域名`，不带结尾斜杠 |
| `APP_DOMAIN` | `你的域名`（给 Caddy 申请证书） |
| `APP_ENCRYPTION_KEY` | `openssl rand -base64 32` 生成；**生成一次就别再改**，另外抄一份放在备份以外的地方 |
| `LLM_*` | 服务器默认的模型（可留空：那就每个人在设置里填自己的） |

```bash
mkdir -p data backups && sudo chown -R 1000:1000 data backups   # 容器里以 node（uid 1000）运行
docker compose up -d --build
docker compose ps            # app 显示 healthy
curl -s https://你的域名/api/health   # {"ok":true,"db":"ok"}
```

### 第一个管理员与邀请码

```bash
docker compose exec app node apps/server/dist/cli.mjs create-admin 你的用户名
```

它会让你输入密码（不回显）；默认时区 Asia/Shanghai，别的时区加 `--tz Asia/Tokyo` 这样的参数。

给朋友发邀请码（一次性、7 天内有效）：

```bash
docker compose exec app node apps/server/dist/cli.mjs invite --note 小明
docker compose exec app node apps/server/dist/cli.mjs invites      # 还没用掉的码（只显示备注和期限）
```

朋友打开网址 → 登录页点「有邀请码？注册一个」→ 填用户名、密码、邀请码。时区自动取他手机的。

### 其他管理命令

```bash
docker compose exec app node apps/server/dist/cli.mjs users                 # 列出账号
docker compose exec app node apps/server/dist/cli.mjs reset-password 用户名  # 忘了密码：重置，并让他所有设备下线
docker compose exec app node apps/server/dist/cli.mjs disable 用户名         # 停用（立即下线）；enable 恢复
```

管理员在 App 里没有任何查看别人数据的界面；技术上能接触到的就是 `data/` 里的数据库和照片（告知页写明了这一点）。

## 2. 更新版本

```bash
git pull
docker compose up -d --build
```

- 数据库迁移在服务启动时自动跑（Drizzle）；存档内容靠 JSON 里的版本号向前兼容
- 前端是 PWA：已经打开的用户会在「回到大厅、手上没有执行中的单」时自动切到新版本
- 改了表结构的版本，更新前先手动备份一次（见下）

## 3. 备份

`backup` 命令用 SQLite 的在线备份（不停服、WAL 下也一致），再复制证据照片和导入前快照：

```bash
docker compose exec app node apps/server/dist/cli.mjs backup --keep 14
# → ./backups/20261121-030000/{app.db, uploads/, snapshots/}，只留最近 14 份
```

每天自动备份：在宿主机 `crontab -e` 加一行（换成你的路径）：

```cron
0 4 * * * cd /srv/host-system && docker compose exec -T app node apps/server/dist/cli.mjs backup --keep 14 >> backups/backup.log 2>&1
```

再把 `backups/` 同步到另一台机器或对象存储（例如 `rclone sync backups remote:host-system-backups`、`restic backup backups/`）。
**`.env`（尤其 `APP_ENCRYPTION_KEY`）不要和备份放在一起**；但要另外存一份——没有它，用户自己填的 Key 解不开（存档不受影响，只是要重填 Key）。

## 4. 恢复

```bash
docker compose stop app
# 留一份现场（以防万一）
mv data data.broken-$(date +%Y%m%d%H%M)
mkdir data
B=backups/20261121-030000          # 选一份备份
cp $B/app.db data/app.db
cp -R $B/uploads data/ 2>/dev/null || true
cp -R $B/snapshots data/ 2>/dev/null || true
sudo chown -R 1000:1000 data
docker compose start app
docker compose exec app node apps/server/dist/cli.mjs users   # 账号都在
```

注意：不要只拷 `app.db` 而漏掉旧的 `app.db-wal` / `app.db-shm`——恢复时 `data/` 里只放备份里的 `app.db`。

单个用户的存档坏了（主档和服务端备份都读不出来，App 提示「联系管理员」）：坏档原串留在 `save_corrupt` 表里，可从全库备份里取那一行恢复；也可以让他用自己导出的 JSON 在设置里「导入存档」。

## 5. 从旧版（纯前端 PWA）迁过来

旧版数据只在各自手机的浏览器里，不会自动迁：

1. 在**旧网址**打开 App → 设置 → 导出存档，得到一个 JSON 文件
2. 打开新网址、登录 → 设置 → 导入存档，选这个文件（格式 / 版本不对会拒收，不动数据；通过后先给当前数据留快照再整体覆盖）
3. 模型设置不在导出包里：要用自己的 Key 就在新版设置里重新填（服务器加密保存）

## 6. 不用 Docker（可选）

Node 22.12+，在仓库根目录：

```bash
npm ci
npm run build
NODE_ENV=production APP_ORIGIN=https://你的域名 APP_ENCRYPTION_KEY=... DATA_DIR=/var/lib/host-system \
  node apps/server/dist/main.mjs
```

前面自己配 Nginx / Caddy 反代到 8787（SSE 路径 `/api/stream` 关掉缓冲：Nginx 用 `proxy_buffering off;`），并设 `TRUST_PROXY=1`。管理命令换成 `node apps/server/dist/cli.mjs …`。

## 7. 排错

| 现象 | 看哪里 |
|---|---|
| 容器起不来 | `docker compose logs app`：缺 `APP_ORIGIN` / `APP_ENCRYPTION_KEY` 会直接写明 |
| 登录后马上又回登录页 | `APP_ORIGIN` 和浏览器地址栏不一致（Origin 校验失败）或不是 https（Secure Cookie 存不下） |
| 拆解一直报「还没配 Key」 | 服务器没配 `LLM_*`，用户也没在设置里填自己的 |
| 报「今天额度用完了」 | 用的是服务器默认 Key 且到了每日上限；调 `LLM_DAILY_*` 或让他填自己的 Key |
| 进度卡不动 / 视觉结论不回来 | 反代缓冲了 SSE：Caddy 配置里保留 `flush_interval -1`；Nginx 加 `proxy_buffering off` |
| 日志 | 一行一条 JSON；不打印 Key、Cookie、口令、照片内容 |

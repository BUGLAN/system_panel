## 0 · 三句话结论

1. **「UI 第一版」成立，「能给别人用的第一版」还不成立。** UI 语言（卡牌皮肤、进度带、动效纪律）已经成体系；但当前有 **3 个 P0**：**连击被每次冷启动清零**、**iOS 拍证据必崩**、**派单板可以二次接单静默吞掉前一张**。另有一个 **P0 级交付风险**：**v1 UI 还没有冻结**——10 个文件未提交，体检期间 `main_view.dart` 在我眼前被并行会话改写（01:01 编译不过 → 01:03 修好）。
2. **功能上最要紧的三个空洞是「记不住 / 叫不醒 / 带不走」**：失败与补救整条链**不落盘**（杀进程即失忆，还会显示一张假补救单）、**零通知**（换日、连击、截止全靠用户自己想起打开 App）、**零备份**（5 个存档 key 全在本机，卸载即全丢）。
3. **流程上真正没定过的只有一件事：期限算不算数。** 周期计划按「天数」生成了 180 张单，但**没有任何节奏约束**——在手窗口恒 3 张、交一张补一张、日上限只数日常单，理论上**一天就能把「半年健身」刷完**。配套的还有「兑现单先交即收官」「日上限 6 形同虚设」「没有『已提交待验』态」——这些是规则问题，不是 bug（§6）。

- 本文**没有**碰 `main_view.dart`，也没有碰任何代码文件。

### 1.4 没验的（诚实清单）

真机/模拟器全部没跑（按 `AGENTS.md`「宿主即测试员」约定）；软键盘、iOS 实机、通知到达率、SharedPreferences 落盘时机、365 张计划的真机卡顿，均为**代码级推断**。大音频/大存档/后台被杀等场景未实测。

## 3 · P0（阻塞第一版可用）

### P0-1 · v1 UI 未冻结 + 工作区一度编译不过（交付风险，**错误本身已修**）

- **经过（实测时间线）**：
  - `00:55` 起 `app/lib/widgets/main_view.dart` 处于**未提交的改动状态**；
  - `01:01` 我跑 `cd app && flutter analyze lib` → `error - The name 'kScaleSlots' is already defined ... lib\widgets\main_view.dart:91:20 - duplicate_definition`（`:85` 与 `:91` 各一份，注释还不一样：一个说「最多分几格」、一个说「最多分几段」）→ **那一刻整个 App 无法构建**；
  - `01:03` 同一命令 → **`No issues found!`**：重复声明已被删除（同一时刻文件 mtime 也在变）。
- **所以本条不是「有个 bug 要修」，而是三件事**：
  1. **v1 UI 只在工作区**（10 个未提交文件）。宿主判定的「第一版」需要一个**提交 + 冻结**的动作，否则所有人（含本文）都在审一个移动靶。
  2. **存在并行写入**。`main_view.dart` 在我读取期间被第三方改写，且不同读取者看到的错误数不同 —— 这正是 `AGENTS.md` 立「单文件同时只允许一个 Agent 写」规矩要防的情形。**请宿主确认是谁在写、是否已收工**。
  3. **`flutter analyze` 不是可选项**：这次是靠它当场抓到的。建议把「提交前 analyze 归零」当作 v1 冻结的硬门槛。
- **方向**：确认写入者 → 等其收工 → 跑一次 `flutter analyze` + `flutter test` → 把 v1 UI 提交成基线（本文后续所有条目都应以那个基线复核）。

### P0-2 · 连击被每次冷启动清零（连击机制事实不可用）✅已复核

- **现象**：连击判定依赖 `_lastDoneDay`（`quest_flow.dart:250`），它**只存在于内存**；而判定写的是「`_lastDoneDay == null` → `streak = 1`」（`:782-790`）。存档 `SaveData` 只有 `host/goal/queue/activeJson/lastSeen`（`save_file.dart:111-130`），**没有这个字段**。
- **后果链**：用户重启 App → 交今天第一单 → `streak` 被**直接改写成 1**（不是 +1，「昨天交过」的信息已丢）→ 覆盖掉已持久化的真实连击。于是 `streak3`/`streak7` 称号、连击药丸、毒舌引用的连击数**全部失真**，而且**越勤快的用户（每天开 App）受害越早**。
- **同族问题**（同一批运行时态，全部不落盘）：`_failStreak`（连败三档毒舌，`docs/12`）、`_retreatDay/_retreatToday/_retreatTotal`（退缩满 3 次挂「口头巨人」，`quest_flow.dart:1050,1154`）、`_titleBeforeShame`（`:261`）。⇒ **重启一次，「连败」与「退缩」档案清零；而「口头巨人」一旦戴上又可能永久摘不掉**（`titleBeforeShame` 丢了，`:850-853` 的还原条件依赖它）。
- **方向**：把这几个「跨日才有意义」的计数并入 `SaveData`（或从 `host` + 最后完成日推导），并补一条「冷启动后连击仍连续」的回归测试。这是**数值真源**类问题的第三次复发，建议顺带立一条机制（见 §8 批次一）。

### P0-3 · iOS 拍证据必崩（缺用途声明）✅已复核

- **现象**：`app/ios/Runner/Info.plist` 全文**零** `NS*UsageDescription`；而证据拍照走 `ImagePicker().pickImage(...)`（`vision.dart:154`），相册选择同样走它（`exec_panel.dart:890`）。
- **后果**：iOS 目标下**整条证据链不可用**——第一次拍照/选图即被系统终止（iOS 强制要求 `NSCameraUsageDescription` / `NSPhotoLibraryUsageDescription`）。而 `AGENTS.md` 明确 iOS 是双端目标之一，`docs/18` 十条设计要求里的第 4 条就是「拍照打卡 + LLM 视觉校验」。
- **方向**：补两条用途声明（中文文案照人脸设写好）；顺手清掉 `Info.plist` 里 WebView 路线遗留的 ATS 配置（路线已删，`pubspec.yaml:61-68` 的注释与它已不对应）。

### P0-4 · 派单板能二次接单，旧单被静默吞掉 ✅已复核

- **现象**：`accept()` 直接覆盖 `_active`（`quest_flow.dart:623-628`，**无判空**）；派单板 `onAccept` 只查 `_busy`（`main.dart:1353-1358`）；底栏中央环永远放行（`dock.dart:53` `running` 恒 false，所以收起执行面板后回大厅 → 再点中央环 → 又进派单板）。而**主线页同一件事是拦住的**（`main.dart:2551-2555` 查 `_flow.active != null` 并插话「手上还有一张没交」）。
- **后果**：前一张单**已出队**（`accept` 先 `removeWhere`），被覆盖后**连同计时起点、证据、已挂道具标记一起消失**，且没有任何提示。用户视角＝「我的单呢？」
- **方向**：`accept` 加 `_active` 守卫（或返回失败），派单板入口与主线页用**同一套**「手上还有一张」守卫。⚠️ 修这个时注意 `main.dart:2557-2563` 的既有踩坑注释：接单必须只走 `_beginExec()` 一条老路。

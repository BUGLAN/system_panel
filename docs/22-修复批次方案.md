## 2 · 逐项：现象 / 根因 / 修法 / 验收

### 2.0 · 全局约束：严格模式（宿主 2026-10-10 追加）

**宿主原话**：「不要做任何兜底，出现问题直接报错，这样我们开发阶段能更快知道问题所在」。

**落地口径（已与宿主确认边界）**：

| 构建 | 行为 |
|---|---|
| `debug` / `profile` | **严格模式默认开**：LLM 失败**不伪装成正常回复**——聊天里给一条红色诊断条目（HTTP 状态 / 超时 / 正文为空 + 原始回执片段），日志打全，**不产兜底台词** |
| `release` | 兜底照旧（无 Key / 断网不得阻塞开局与提交，仓库铁律），但兜底**必须显式标注原因**并计入遥测 |
| 设置页 | 新增「严格模式」三档（自动 / 开 / 关），可手动覆盖构建默认值（便于在 release 上验） |

**两条附带要求**：
1. **兜底从「默默发生」变成「可观测事件」**：每次失败计数（按失败类别）+ 保留 `LlmReply.detail` + 日志一行；设置页回显「最近一次 LLM 失败原因」。
2. **一处例外要写清**：发布/结算/毒舌这类**文案**在严格模式下也不中断（演出不能因为模型出错而崩），它走「日志 + 遥测 + 设置页回显」而不是红条；聊天是唯一能把错误直接摆到宿主面前的地方。

> 与 D-j（模板兜底保留）的关系：模板兜底是**无 Key / 断网时的产品降级**，严格模式管的是**「出错时你知不知道」**——两者不冲突：release 兜底但标注，dev 直接报错。

### R1 · 「和小祥聊天」永远兜底（P0，另有两条同根）

**现象**：首页打字聊 → 显示「思考中」→ 固定兜底毒舌（宿主截图那句：「这会儿连不上我。连不上也得干活——你手里那单不会自己完成。」）。宿主说「llm 已配置」。

**根因（已实锤，非推测）**：端点上 `deepseek-flash` 是**推理模型**，`max_tokens` 同时覆盖 `reasoning_content` + `content`；聊天只给 **200**（[chat_service.dart:176](../app/lib/chat/chat_service.dart#L176)），文案侧只给 **120**（[copy.dart:336](../app/lib/agent/copy.dart#L336)）。思考经常把预算吃光 → HTTP 200 但正文为空 → [llm_gateway.dart:46-47](../app/lib/agent/llm_gateway.dart#L46-L47) 返回 null / [chat_service.dart:184](../app/lib/chat/chat_service.dart#L184) 判空 → 走兜底。

**证据链**：
- 设备设置正常：`baseUrl=https://api.deepseek.com`、key 有效、`model=deepseek-v4.1flash`（会被别名归一成 `deepseek-flash`，[llm_client.dart:56-66](../app/lib/agent/llm_client.dart#L56-L66)）。
- 设备聊天历史：13:40:38.758 发「你好」→ 13:40:40.657 兜底（**1.90s = 真实往返**，不是断网 12s 超时、也不是无 Key 的 22ms 分支）。
- 兜底句选择是**确定性**的（[chat_service.dart:63-69](../app/lib/chat/chat_service.dart#L63-L69) 的 `_pick`）：复算「你好|5」→ `fallbackLines[1]`，与截图逐字相同 ⇒ 每次重发同一句都回同一句，宿主看起来像「没反应」。
- 直连端点复现（用 App 里那把 key，persona prompt + 6 个工具，`max_tokens=200`）：`finish_reason=length`、`content=""`、`reasoning_tokens` 把预算吃满；同一形状的第二次往返（工具回执）思考更长，正文更空。
- 附证：设置页「测试连接」用的是 `maxTokens: 8`（[llm_client.dart:190](../app/lib/agent/llm_client.dart#L190)），**永远绿**，所以「测连接通了、聊天却兜底」＝结构性错觉。
- 诊断盲区：整条 LLM 路径**零日志**，`LlmReply.detail`（HTTP 状态/超时原因）构造出来后被丢弃（[llm_gateway.dart:45](../app/lib/agent/llm_gateway.dart#L45)、[chat_service.dart:178-181](../app/lib/chat/chat_service.dart#L178-L181)）——这也是「无法验证」的成因。

**修法**：
1. 抬上限：聊天 200 → **1024**；文案 120 → **512**（[chat_service.dart:176](../app/lib/chat/chat_service.dart#L176)、[copy.dart:336](../app/lib/agent/copy.dart#L336)）。
2. 请求带 **`reasoning_effort`**，默认 `low`（端点在 `/models` 自报 `supported_levels: low/high/max`，实测 low 时同一句更快拿到正文）；设置页 LLM 组加一个「思考档位」高级项。
3. **失败可见化**：`LlmReply.detail` 不再丢——`debugPrint('[llm] …')` + 聊天里一条诊断条目（沿用 `〔工具〕` 的等宽系统条目样式，如 `〔诊断〕`），把 HTTP 状态 / 超时 / 空正文分开说。
4. 「测试连接」改用**真实形状**（persona + 真实 `max_tokens`），不再用一个永远绿的探针。
5. 新增测试：**HTTP 200 但 content 空**、`finish_reason=length`、只有情绪标签、`reasoning_effort` 透传。
6. **严格模式（§2.0）**：`debug/profile` 下失败不产兜底台词 → 聊天里红色诊断条目（`〔诊断〕` + 失败类别 + `detail`）+ `debugPrint` + 遥测计数；`release` 下兜底但标注「这是兜底 + 原因」。设置页加「严格模式」与「思考档位」两行。

**验收口径**：在 MuMu 现档发「你好」→ 正文非空且是人设句（引用真实队列数字）；logcat 能看到请求与回执；**坏 Key 时严格模式给红条且不产假台词、release 模式给兜底且标注原因**；设置页「最近一次失败原因」有值；`flutter test` 全绿含新用例。

**同根一并修**：发布/结算/毒舌/追问的 AI 文案（`copy.dart`）。

### R2 · 「对话即操作」无法验证（不单独修）

**事实**：真 LLM 工具循环是被 R1 同一个 `max_tokens` 饿死的（工具回执那轮思考更长）；无 Key 快捷 chip 那半**本来就是好的**——chips 只判 `enabled && !thinking && onQuickTool != null`，不判 key；设备历史里 10-09 23:07 有一条真实的 `〔工具〕get_status` 记录。

**修法**：R1 修完即通。**验收口径**：① 无 Key 下点三个快捷 chip（查状态/换任务/调整计划）全部真实生效；② 有 Key 下说一句「我现在什么状态」，她经工具回执后给出引用真实数字的回答；③ `swap_quest` / `adjust_plan` 会真改队列——**实测前先问宿主**（D-l）。

### R3 · 声音与震动（整项从零）

**现状**：`app/lib` 里 audio / vibrate 相关**零命中**；`sound / haptic / voice / holo` 四个开关能存能显示但**没人消费**——[main.dart:376-383](../app/lib/main.dart#L376-L383) 对非 LLM 变更直接 early-return，`main.dart` 也不持有 settings 字段（[settings.dart:2](../app/lib/state/settings.dart#L2) 注释自承「这里先只是数据」）。原型侧参数完整可烘焙：[audio.js:70-135](../prototype/opus-v2-dir/js/audio.js#L70-L135)（26 事件 + 4 连续音）、[motion-demo/index.html:307-322](../prototype/motion-demo/index.html#L307-L322)（8-bit 音效表）、`util.js:123` `buzz()` + 15 处波形。

**修法**：
1. **前置接线**：`main.dart` 持有当前 `AgentSettings`，非 LLM 变更也分发到消费方（这是声音、震动、节奏三者共同的前置，也是 TODO-23 的前置）。
2. **素材**：新增离线烘焙脚本（`tools/audio/`），按原型参数渲染成 `app/assets/audio/`（`.wav`/`.ogg`），含**每发随机音高变体**烘成 N 版（原型 `rand(.92,1.08)` / `1700+rand*300` 不能丢）。⚠️ `pubspec.yaml` 声明 assets **不递归子目录**，逐个列。
3. **范围**：高频 12 件（tap / choose / 落板 land / 稀有度滚 rung / 落定 rank / 按满接单 seal / 发布 ding / 砸印 impact / count / 暴击 crit / 升级 levelup / 失败 fail）+ **打字机逐字音节**（34ms 一发，需池化播放器）+ 环境底噪（可关）。
4. **依赖**：`audioplayers`（AGENTS.md 点名）+ 池化方案（`hold` 每 1/8 步、`count` 每 55ms、逐字音节都是高频一发）。
5. **震动**：`vibration` 插件 + `AndroidManifest.xml` 加 `VIBRATE` 权限，还原 15 处波形（启动 `[10,60,20]`、砸印 `[40,30,60]`、暴击 `[20,20,40]`、升级 `[30,50,30,50]`、落定 `[20,30,50]`、接单 `[30,40,60]` + 单值若干）。
6. 事件挂点沿用原型调用点（例：`plate.dart:975` 的按住每 1/8 步处已留注释「原型在此处放音效 + 5ms 震」）。

**验收口径**：① logcat 有「事件 → 播放」记录，`adb shell dumpsys audio` 能看到活动流；② 关掉「音效」开关后同一操作**无**播放；③ 冷启/落板/接单/结算/升级逐个事件实测出声（宿主本人在 MuMu 上听）；④ 震动用 `dumpsys vibrator` 证明波形调用发生。**明确不可验收**：音质/响度平衡/震感——留到真机轮。

### R5 · 开机自检与唤醒（裁决 D-d / D-m）

**现状**：开机屏有日志/进度条/TIPS/「触碰屏幕 · 唤醒系统」，**但她全程什么也没做**——boot 期间一次舞台指令都没下发（`main.dart` 里 `sleep`/`dozing` 零命中），「睡」这一拍完全没移植（原型见 [flows.js:54-61](../prototype/opus-v2-dir/js/flows.js#L54-L61)、睁眼节拍 [flows.js:80-84](../prototype/opus-v2-dir/js/flows.js#L80-L84)）。门禁是「第 1 帧起任意处点击 = 直接进大厅」，把整段日志一起跳过。

**本轮修法（只做不靠她身体的那一半）**：
1. 日志节奏收紧、进度条与「唤醒序列就绪」的拍子对齐；呼吸提示保留。
2. 唤醒演出＝**全屏亮帧**（`_pulse`，原型 `FX.flash('#9ff0ff',.26,520)`）+ **音效**（`boot`）+ **震动**（`[10,60,20]`）+ **推镜头**（`camOf` boot s.64 → lobby s.92，已在跑，弹簧 k=70/zeta=.95）+ 逐个点亮主线环。
3. 门禁改为：**点任意处 = 触发唤醒这一拍**；日志未滚完时点击**先快进日志**再演唤醒；演出开始后不可二次跳过。

**Mac 轮验收项（本轮不做，写死在这里防丢）**：她闭眼（`ParamEyeLOpen/ROpen` = 0，注意桥接表里 `sleep` 指向的 `exp_idle04` 眼参数是 **1.0**，不等于闭眼）→ 触碰后抬眼皮颤两下（lid `.35 → .05`）→ 睁眼看向宿主 → 欢迎手势（动作组 `kime`/`smile`）；以及舞台通路本身（原生 `param()` 可用 / WebView 侧 `stage.js` 只有 `probe/cam/geo`，7 处 `_stagePort` 调用当前被 `try{}catch{}` 静默吞掉）。

**验收口径**：冷启 → 点任意处 → 演出按拍播完再进大厅（录屏/逐帧截图）；日志未滚完时点击先快进；音效开关关闭时唤醒无声音但演出照常；`gfxinfo` 无新增 jank。

### R6 · 派单卡顿（先测量，不盲改）

**宿主原问**：是优化问题、模拟器配置太低、还是换真机就好？

**现有证据**：Flutter 侧 **284,818 帧 / janky 0.00%（legacy 0.09%）/ p50/90/95/99 = 5ms**（本次实机读取）；舞台自报 `[stage-web] rAF 60fps · worst 17ms`（偶发 50~67ms，探针见 [stage.js:77-90](../app/assets/stage/stage.js#L77-L90)、[live2d_web.dart:209-212](../app/lib/stage/live2d_web.dart#L209-L212)）。嫌疑集中在两点：**WebView 合成路径**（`dumpsys gfxinfo` 统计不到平台视图，见 docs/20 §2.1②）与 **debug/JIT 构建**（仓库自己实测 debug 吃 205% CPU、janky 72%→38%，见 `.verify/emulator-perf/README.md`）。

**本轮修法**：装一次 **profile 构建**（同包名、同调试签名、**不 `pm clear`，存档不丢**）→ 重跑 `dumpsys gfxinfo` + 读舞台 rAF → 与基线对比 → 出结论报告。**数字出来前不做任何优化**。

若 profile 下 Flutter 侧仍掉帧，候选靶点（需证据支持再动）：[fx_particles.dart:342](../app/lib/widgets/fx_particles.dart#L342) 每帧全画布 `saveLayer` + `BlendMode.plus`、[plate.dart:1240-1243](../app/lib/widgets/plate.dart#L1240-L1243) 指纹呼吸 2200ms `repeat()` 常驻。**舞台本身的渲染路径归属留到 Mac 轮**（D-c）。

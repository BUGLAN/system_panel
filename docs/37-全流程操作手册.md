## 0 · 环境与复现命令

| 项 | 值 |

## 1 · 主流程（冷启动 → 结算，11 步）

| # | 操作 | 预期 / 要点 |
|---|---|---|
| 1 | 冷启动，**点屏幕任意处** | 开机自检（`SYS//BOOT · v2`、逐行日志、`触碰屏幕 · 唤醒系统`）；点一下即唤醒，日志没滚完会先快进 |
| 2 | 唤醒过场 | 她睁眼 + 推镜头 + 进度带亮起，落到**绑定 · 目标**幕：预设卡横滑 + 输入框「目标 › 比如：三个月跑完半马」 |
| 3 | 点预设卡填词 → 点【确定】 | 预设卡只是**填词**；空输入点确定 → 输入框内联红字「空的她拆不动」；空话（<2 字/黑名单）她追问「太空了。说点具体的。」 |
| 4 | 访谈卡 01/03→03/03，逐张点答案 | 每题 3~4 张答案牌 +「自己写」幽灵牌；**只能前进，无返回**（见 §3） |
| 5 | 答完自动生成 | 进大厅：见面礼横幅（双倍卡 ×1）、HUD（六边等级牌 / 称号 / 金币 / 右上三横线）、底栏（主线·档案·补给 + 中央大环「委托」）、右下圆钮=聊天 |
| 6 | 点底栏中央**「委托」** | 派单板：任务卡（编号 `№`、稀有度、附言、证明、时限、报酬）+ **指纹「按住 · 接下」** + 板下两颗「宿主 · 换一个」「宿主 · 等会儿」 |
| 7 | **按住指纹 0.9~1.2s 松手** | 接单成功 → 执行面板。**按不到就松手**她会说「手抖什么。」（本轮实测），不算接单 |
| 8 | 执行面板 | 标题 `执行中 · MAIN n/m` + 大计时 + 时限条 + `SYSTEM 正在看着你` + 证据槽 + 暴击率；底部【道具】【提交 · 让她验收】，最底【按住 · 认输】【收起 ▾】 |
| 9 | 点空证据槽 → 点领位牌 | 弹两张来源牌：领位「拍照」/ 侧牌「从相册选」。**MuMu 上"拍照"可用**（拉起模拟器相机 → 快门 → ✓ 确认）；落槽后缩略图带「未校验」徽章，无 Key 时红字「未校验 · 未配置 Key」，暴击率 6%→10% |
| 10 | 点【道具】→ 点抽屉领位牌 | 道具即用即扣（双倍卡 → 芯片「×2」，EXP 1→2） |
| 11 | 点【提交 · 让她验收】 | 结算屏：`CLEAR · 主线第 N 单` + EXP/金币/维度/连击芯片 + 暴击判定文案（约 3~4s，**不能点跳过**）→ 出口轨 |

**出口轨怎么选（关键）**：出口牌是一条**横滑轨**，只有**领位牌**是选定项 —— **横滑换牌 → 点领位牌确认**。直接点侧牌不换位（本轮实测两次无效）。

## 3.5 · 「点委托 → 等会儿」回大厅时闪一帧（宿主录屏指认，已定位到帧）

**现象**：点【委托】进板正常；点【等会儿】回大厅时，**有一帧她整体错位**（实测头顶从 y=275 掉到 y=1088，且水平偏左、下半身出画），下一帧即恢复。同帧 Flutter 自绘的 HUD **纹丝不动**（左上 LV 徽章逐帧 51–111，全片一致）→ 不是整屏位移。

**取证**（`adb shell screenrecord` 60fps 录屏 + 临时探针，探针跑完已撤、两文件 md5 复原）：

| 项 | 值 |
|---|---|
| 全片异常帧数 | 841 帧里**恰好 2 帧**（两次「委托→等会儿」各一帧），位置一致 |
| 异常帧时刻 | 「等会儿」视觉起点后 **0.30~0.40s**（`rec.mp4` f0336；`rec2b.mp4` f0389） |
| 探针日志 | `[probe] plateAlt i=1` = 14:22:08.402 → `[probe] family 1.7 -> 1.05 camS=1.0467` = 14:22:08.793（**+391ms**） |
| 对齐结果 | 探针反推的视频时刻与异常帧相差 **≤1 帧** |
| 方向性 | **进板（1.05→1.70，放大）不闪**；只有**出板（1.70→1.05，缩小）闪** |

**根因**：`live2d_stage.dart` 的「固定尺寸族 + Transform」——`kViewFamilies = [1.05, 1.70]`，而**只有 `talk`（派单）用 1.70 族**（`camera.dart` 的 `Cam.all`：lobby/exec/fail/panel/boot/full/result 全 ≤1.05）。于是每次进出派单板，**平台视图的布局矩形真的改尺寸**：`StageCalib.kSize = 1.0`、`dx=dy=0` ⇒ 1.70 族 = 780×2870，1.05 族 = 780×1772。视觉上两者等价（`矩形 × k` 恒 = `H·cam.s`），但 Android 平台视图是**真 View / GL surface**，缩小那一帧 Flutter 已按新矩形合成、原生侧还在按旧 surface 出图 → 单帧错位。放大方向不需要重配旧图，所以不闪。

**修法**（宿主 2026-10-13 拍板：「增加动画，不出现这种闪的画面」→ **已实现**）

- ✅ **已落地 · 「重绘」过场**：新增 [`app/lib/stage/redraw_veil.dart`](../app/lib/stage/redraw_veil.dart)，在 `main.dart` 的 Stack 里挂在**她之上、环场之下**（`ProgressBand` 之前）——
  - 换族那一帧（`viewFamilyS` 变化，由同一条 `_cam` 通知链驱动，**同帧**生效）起，遮罩**满不透明约 3 帧**（≈50ms），随后 100ms `easeOutCubic` 软退，`t=0…0.75` 间一道电光青**扫线自下而上**掠过（`CustomPaint`，不用 `Opacity`——`saveLayer` 吞平台视图）。
  - **为什么必须满盖 3 帧**：实测平台视图改布局尺寸后**要 2~3 帧才换上新 surface**，第 2/3 帧她会被渲染成"小号"错位（未修复录屏：`rec.mp4` n=336 一帧；加遮罩后：`rec3` 的 n=342/343 仍能看到小号她）。
  - **为什么只压她不压屏**：遮罩在环场**之下**，环场/进度带/HUD/台词/底栏都在它上面 → 观感是「**她重绘一拍**」，不是整屏黑一下。
  - reduced-motion（`maybeDisableAnimationsOf`）：**不播扫线、不留淡出**，只做 3 帧静态切换（80ms 控制器）—— 一帧都不能少，少的那几帧就是她露出来的那几帧。
- 验证（60fps 录屏 `rec6.mp4`，4 次换族：2 进板 + 2 出板）：每处都是「约 4 帧内她不可见 → 带扫线恢复」，**全片无任何错位帧**；`flutter analyze` 0 issue、既有测试 61 项通过。reduced-motion 用 `settings put global animator_duration_scale 0` 实测同样覆盖（`rec5.mp4`）。

**其余候选（未采用，留档）**

- **A · 只留一族**：`kViewFamilies = <double>[1.70]` —— 布局矩形恒定、永不 resize，从根上消除；几何完全等价（缩放本来就由 `Transform.scale` 表达），iOS 侧「不逐帧重建 FBO」的收益也保留。**代价**：常驻 GL surface 从 1772px 高变 2870px 高（≈2.6× 像素），低端机有显存/填充率风险。
- **A′ · 单族 + 把派单推镜头调浅**：`talk.s` 1.70 → 约 1.25、族取 1.25，surface 只比今天大 ~19%，代价是派单时她不再怼到脸前（观感变化）。
- B · 换族挪到看不见的时刻（点「等会儿」当下就换）：她上半身在板上方仍可见，**仍会闪**，不彻底。
- C · 插件（`flutter_live2d 1.0.2`）**没有** scale/resolution API，把缩放交给原生需改插件。

**单帧问题的取证套路**（本轮现学，复用时照抄）：
```bash
adb shell screenrecord --time-limit 14 --bit-rate 12000000 /sdcard/rec.mp4   # 60fps
# 驱动操作，然后：
ffmpeg -i rec.mp4 -vf scale=234:506 -q:v 4 frames/f%04d.jpg                # 抽帧
# 逐帧算与前一帧的 mean abs diff → 取尖峰；再按特征量（如「她头顶所在行」）揪出单帧异常，
# 最后 ffmpeg -vf "select=eq(n,<帧号>)" 出全分辨率该帧人工确认
```
> ⚠️ `ffmpeg -vf select` 的 `n` 与 `scale` 抽帧的编号会差几帧，**别跨两种方式对帧号**；定位到候选后统一用 `select=eq(n,...)` 复核。
> ⚠️ bash 里 `/sdcard/...` 会被 MSYS 改写成 Windows 路径 → 命令前加 `export MSYS_NO_PATHCONV=1`，而**本地路径要写成 `E:/...`**。

> 网格校正图（`*_grid.png` / `*_top.png` / `*_bottom.png`）是量坐标用的中间产物，复跑时按 §0 的坐标纪律重出即可。

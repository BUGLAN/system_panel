# 47 · Live2D 清晰度修复全过程（2026-10-23 ~ 10-24）

> 这是一份**过程复盘**：从宿主说「不够清晰」到「iOS 定案」这两天做了什么、怎么量的、错在哪里。

## 一、一句话结论

| 平台 | 病根 | 处置 | 结果 |
|---|---|---|---|
| MuMu（Android） | 面板只给到 DPR 2，且 `wm size` 覆盖会让 SurfaceFlinger 多插一次缩放 | 面板改 1170×2532@480（DPR3，逻辑尺寸不变） | 中频 **+110%** |
| iOS 真机 | DPR 恒为 3，**贴图相对屏幕本来就 1:1**（mip LOD 1.07~1.22）⇒ 采样器没有可榨的细节 | **超采样**：平台视图按 1.55 倍屏高渲染（大厅 1.68×）再缩回；**mipmap 保持原版** | 中频 **+64~69%**，无锯齿 |

**别再做的事**：关 mipmap（拿锯齿换锐利）、加贴图分辨率（mip 会归一化）、shader LOD bias（GLES2 不支持，模型直接不渲染）。

## 二、时间线（每个阶段的输入 → 判断 → 动作）

### 阶段 0 · MuMu：先解决「能测」再解决「清晰」（10-23）

- 输入：宿主「一直感觉比原数据糊」
- 判断：模拟器 DPR 只有 2，而且靠 `wm size` 覆盖时 SurfaceFlinger 还在缩放（`sourceCrop ≠ displayFrame`）
- 动作：面板原生改 1170×2532@480（宽高比与旧档完全一致 ⇒ 零布局位移）+ 清掉 wm 覆盖
- 结果：中频 +109.7%，高频反而下降（旧的「高频」是放大走样）——**这条教训贯穿全程：高频不能单独当作清晰度指标**

### 阶段 1 · iOS 关 mipmap：被证否（10-24 凌晨）

- 输入：宿主「放到 iOS 手机上有点模糊」
- 当时的判断（文档 §3.1 写的）：贴图只有 124 texel、屏幕上 47.8px ⇒ 只用到 38.6% 的贴图分辨率 ⇒ 关掉 mipmap 放细节
- 动作：三口径各构建一次（原版 / mip 近邻 / 关 mipmap），同机同机位截帧比（§3.7）
- 结果：**中频 +219%，但高频 +133~2200%**，肉眼是发丝/腮红/缎带上的**点状噪光**
- 宿主验收：**「锯齿太多了」** ⇒ 证否

### 阶段 2 · 把「贴图密度」量死：发现前提是错的（10-24）

- 动作：连通域量贴图里的虹膜（96×112 texel，不是 124）；把三种相机的 texel/px、mip LOD 全算出来；再做受控重采样仿真（§3.8）
- 结论：**iOS 上 LOD 1.07~1.22 = 贴图与屏幕正好 1:1**，mip 并没有「再砍一半」；关 mipmap 换来的不是细节，是混叠
- 教训：**文档里的推断数字（124 texel / 47.8px / 38.6%）必须实测复核**，一个错了整条推理就歪

### 阶段 3 · 查开源做法 → 超采样（10-24）

- 动作：按宿主指示联网查（官方 Cubism 样例、Flutter 平台视图合成、pixi / Ren'Py 生态）
- 关键出处：官方 iOS 样例就是 `glGenerateMipmap` + `GL_LINEAR_MIPMAP_LINEAR`；Flutter 平台视图缩放由 **CoreAnimation** 做（`kCAFilterLinear`，Impeller 不参与、无 filterQuality 开关）；pixi 用 `resolution: 2`、Ren'Py 用 `mesh_oversample` 修同一类问题
- 判断：业内一致的解法是**保 mipmap + 多渲染像素再缩回去**（SSAA）
- 动作：`kViewFamilies` 小族 1.05 → 1.40（大厅 1.52×），四配置实测（§3.9）
- 结果：中频 +50~53%、高频仅 +74~162%，**肉眼更利且无噪光** ⇒ 定案

### 阶段 4 · 下一档：拉满 + 预锐化 + 撞到天花板（10-24 深夜）

- 超采样 1.40 → 1.55（大厅 1.68×）：中频 +64~69%；同时量清**饱和点**——LOD 撞 mip0 后加像素无效（§3.10）
- 新增 `convert.py --sharpen`（贴图 unsharp，只动 RGB）：发丝中频再 +8%，无光晕
- 两条死路：shader LOD bias（编译失败、模型消失）、继续加大超采样（饱和）
- 结论：**iOS 已经到屏幕分辨率上限**，再加只能靠「插件内后处理锐化」（未做）或改构图（未做，需宿主点头）

## 三、这套量测法（下次直接照抄）

1. **确定性画面**：真机跑 `flutter build ios --release --dart-define=SHOT=lobby`，跳过开机屏直接停在某一页（同一姿势、同机位），避免靠手指点。
2. **固定绝对窗口**：1280×2796 截图取固定坐标窗口（脸 / 领口 / 发丝）⇒ 几何天然归一化，不会把「更大」当成「更清楚」。
3. **四个量一起看**：虹膜像素、中频 0.22–0.38（主判据）、高频 ≥0.60（⚠️ 走样也会进这一档）、梯度 RMS。
4. **一次只动一个变量**：贴图、族尺寸、过滤模式分开测；每档都保留截图与数字。
5. 证据落 `.verify/l2d-clarity-ios/`（gitignore，不入库）：截图、并排图、量测脚本 `lead/*.py`。

## 五、坑与死路（都踩过，附证据）

| 做法 | 现象 | 证据 |
|---|---|---|
| `wm size` 提 DPR | 中频掉 45%（SurfaceFlinger 多一次缩放） | docs/46 §2.1 |
| 关 mipmap | 高频 ×2.8~3.3，发丝/腮红点状噪光 | `.verify/l2d-clarity-ios/{LIN_25,AFTER_2}.png` |
| 只改 wrapper 一处过滤 | 纹理不完整 → 黑剪影 | docs/46 §3.2 |
| 2× Lanczos 上采样贴图 | 高频只 +3%，宿主判「更糊」 | docs/46 §3.6 |
| shader `texture2D(..., -0.5)` LOD bias | **模型整个不渲染**（Apple GLES2 不支持 bias） | `.verify/l2d-clarity-ios/BIAS_92.png` |
| 超采样加到 1.85× | 只多 +5~9%，填充 +40%（LOD 撞 mip0） | docs/46 §3.10 |
| 只看高频判断清晰度 | 走样会伪装成「锐」 | 全程反复踩，最后固定成「中频为主 + 并排图核对」 |

## 六、还没做的（按性价比）

1. **插件内后处理锐化**（离屏 FBO + unsharp/RCAS + 4×4 tent 降采样）：预期边缘对比度 +20~40%，可与现有超采样叠加，是唯一还有大空间的一条；要写约 100 行 ObjC++。
2. **mip 链质量**：现在是 `glGenerateMipmap` 的 2×2 box 且在 gamma 空间生成，细线会被压淡；改线性光 + Lanczos 预滤波，预期 +3~8%，几乎零成本。
3. **`UseHighPrecisionMask(true)`**：只影响部件交界干净度，预期 0~5%，1 行。
4. **构图放大**（`lobby.s 0.92 → 1.05`）：不是渲染问题，是「她占多少屏」，虹膜 46→52.5px；**改观感，要宿主点头**。

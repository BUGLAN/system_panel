## 提示词正文

你要把「宿主养成系统」从**纯前端 PWA**（所有数据存在用户浏览器的 IndexedDB 里，浏览器直连 LLM）改造成**服务器 + SQLite 的多用户全栈应用**。产品本身（玩法、数值、文案、界面、动效、音效）不变，变的是数据放在哪、规则在哪执行、LLM 从哪调、怎么部署。

全程用中文：界面文案、代码注释、提交信息、给我的回复都写中文。

### 一、已定，不要再讨论

| 项 | 定案 |
|---|---|
| 数据库 | **SQLite**（单文件，部署在自己的服务器上） |
| 技术栈 | **TypeScript 全栈**：前后端同一个仓库、同一种语言，`src/core/` 的纯逻辑前后端共用 |
| 部署 | 自己的服务器（不再是 Cloudflare Pages 纯静态）；HTTPS |
| 用户 | 多用户：我自己 + 少量朋友；每人的数据互相隔离 |

- 现有代码的分层：

  - `src/agent/`：LLM 客户端、拆解 / 匹配代理、视觉校验、聊天工具、记忆 —— 改到**服务端**调用

  - `src/ui/`：界面 —— 基本不动，只加登录相关页面、改设置页
- 旧 Flutter 代码在 tag `flutter-final`，一般用不到

### 三、待拍板（在实施计划里给出你的建议和理由，我确认后才写代码）

我倾向下面的「建议」，你可以反对，但要说清楚为什么：

1. **框架**
   - 建议：保留现有 Vite + React SPA 当前端；新增 Node 22 后端，用 **Hono**（`@hono/node-server`）提供 `/api/*` 并在生产环境托管前端构建产物；ORM 用 **Drizzle**，驱动 **better-sqlite3**（开 WAL）；请求校验用 **zod**；仓库改成 `apps/web` + `apps/server` + `packages/core`（npm workspaces）
   - 备选：迁到 Next.js / React Router v7 framework mode 这类一体化框架。如果你建议这条，要评估现有 SPA（场景状态机、转场、Canvas 粒子）迁过去的代价
2. **规则在哪执行**
   - 建议：**服务端权威**。前端只发「意图」（接单、交证据、提交、认输、装道具、购买、补签、佩戴、换一个、立目标……），服务端用 `core/` 跑 QuestFlow、落库、把新状态返回；暴击的随机数、「现在几点」（计时、换日、连胜、补签判定）都以**服务器时间**为准
   - 每个用户的写操作串行（同一用户的请求排队或加锁），状态带版本号，防止两台设备同时操作把档写乱
3. **数据怎么存**
   - 建议：每个用户一行存档（`SaveData` 整体 JSON + 结构版本号 + 乐观锁版本号），沿用现有 `saveToJson / saveFromJson` 与「在默认值上合并」；流水、聊天、长期记忆、证据元数据、LLM 设置、同意记录各自建表；证据照片存磁盘（`data/uploads/<userId>/…`），表里只存路径、大小、哈希、校验状态
   - 有服务器迁移体系：Drizzle 迁移管表结构，存档 JSON 自带版本号管内容
4. **账号**
   - 建议：用户名 + 密码（argon2id 哈希），httpOnly + Secure + SameSite=Lax 的会话 Cookie（服务端存会话表，可吊销）；**邀请码注册**（我在服务器上生成，发给朋友；没有邀请码不能注册）；第一个管理员账号用命令行创建
   - 不做：找回密码邮件、第三方登录、手机号。忘了密码由管理员命令行重置
5. **LLM 和 Key**
   - 建议：LLM 调用全部挪到服务端（顺带解决浏览器 CORS 问题，Key 不再进浏览器）。默认用**服务器环境变量里配的一套**（端点 / Key / 文本模型 / 视觉模型）；每个用户可以在设置里填**自己的**覆盖它，用户 Key 用服务器密钥加密存库，接口永远不回传明文
   - 每个用户的 LLM 调用要有限流和每日上限（防止朋友把我的额度刷爆），超了给清楚的提示
   - 拆解动辄几十秒：建议「提交任务 → 返回任务 id → 前端用 SSE 收进度（识别目标 / 拆这一段 n/2 路 / 规则校验）→ 完成或失败」，替代现在的前端 `withPlanJob`；失败分类与失败卡文案保持现状（noKey / 网络 / 超时 / HTTP / 拒拆……，CORS 这一类在服务端基本不会再出现）
6. **离线**
   - 建议：PWA 外壳照旧离线可开；断网时显示最近一次缓存的状态（大厅、档案只读），所有写操作提示「需要联网」、不做离线排队。计时以服务器的 `startAt` 推导，断网期间界面照常走秒
7. **旧数据**
   - 建议：现在浏览器里的数据，用现有「导出存档」得到的 JSON，登录后在设置里「导入存档」上传到服务端（复用现有包格式与校验：格式 / 版本不对就拒收、导入前先给当前数据做快照）。不做自动迁移

除此之外，任何**规则层面**两边都没写到的问题，列出来问我，不要自己拍板。

### 四、必须保住的东西

- `AGENTS.md`「定案」一节全部行为不变；`docs/03-验收清单.md` A~K 全部仍然成立（措辞随存储位置调整）
- 重置存档：清该用户的存档、备份、聊天、流水、长期记忆、证据照片（磁盘文件也删）、导入前快照；不清账号、LLM 设置、同意记录
- 导出 / 导入：范围与重置一致，照片 Base64 进 JSON；**导出永远不含 Key**；导入先校验、不合格不动数据、通过后先快照再整体覆盖
- 坏档保护：写入前保留上一份好档；读到坏档不静默清零（服务端版：读坏 → 记日志、回退上一份、告诉前端）
- 证据：前端压缩（长边 ≤1024、JPEG）后上传；服务端再校验类型和大小（建议上限 2MB）；视觉校验 30 秒超时不重试；交单时最多等 20 秒；交单即封存、迟到结论丢弃
- 自伤关键词闸门**前后端都要过**（前端为了即时反馈，服务端为了兜底），命中不调 LLM
- 首启告知页改写：说明数据会存在**这台服务器**上、目标 / 聊天 / 照片会发给服务器配置的模型服务商；同意记录跟账号走，告知文案有实质修改时版本号 +1 要重签
- 所有动效、音效、亮帧、转场、键盘适配、安全区、PWA 安装引导保持现状

### 五、安全底线

- 每个查询都按当前登录用户过滤，任何接口都不能读到别人的数据（写测试：A 用户拿 B 用户的 id 去请求要 404）
- 密码 argon2id；会话 Cookie httpOnly / Secure / SameSite=Lax；写接口校验 Origin；登录、注册、LLM 接口限流
- 上传：限制大小与类型、文件名由服务端生成、防路径穿越；照片只能被它的主人访问（不要放在公开静态目录）
- 所有密钥（服务器 LLM Key、加密用户 Key 的密钥、会话密钥）只从环境变量读；日志里不打印 Key、Cookie、照片内容
- 前端代码和构建产物里依然不能出现任何 Key（保留并扩展现有 `scripts/check-dist.mjs`）

### 六、部署

- 建议 Docker（`node:22-slim`）：一个容器同时跑 API 和前端静态文件；`/data` 挂卷放 SQLite 文件和上传的照片；前面用 Caddy（自动 HTTPS）或 Nginx 反代
- SQLite 备份：建议每天用 `sqlite3 .backup`（或 Litestream）备份到另一个目录 / 对象存储，写进部署文档，并给出恢复步骤
- 提供：`.env.example`（只有变量名和说明，没有值）、健康检查接口、首个管理员与邀请码的命令行脚本
- 实际部署由我来做，你写清楚 `docs/02` 的新版部署说明（Cloudflare Pages 那版作废）

### 七、工程要求

- 目录分层：`packages/core`（原 `src/core`，前后端共用，仍然不碰 DOM / Node API）、`apps/server`（路由、鉴权、数据库、LLM、上传、任务）、`apps/web`（原前端）。`agent/` 里纯逻辑的部分（提示词、工具定义、解析）放共享包或服务端，**不要再在浏览器里调 LLM**
- 单个文件不超过 600 行
- 测试：核心逻辑的现有 Vitest 用例全部保留；服务端用内存 SQLite（better-sqlite3 `:memory:`）+ 直接调 Hono 的 `app.request()` 做接口测试，至少覆盖：注册 / 登录 / 会话、用户隔离、接单 → 交证据 → 结算 → 存档落库、认输补救、并发写（版本冲突）、导入导出与重置范围、LLM 失败分类（假端点）、限流
- 每一步都要过：类型检查、`vitest run`、前后端构建；不要用浏览器反复截图量像素来自我验证
- 不要提交 `.env`、`data/`（数据库与上传目录）、`node_modules/`、`dist/`、任何 Key

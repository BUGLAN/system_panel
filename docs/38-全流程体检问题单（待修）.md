## B1 · P0 · 执行中可二次接单，前一张被静默吞掉

**现象**：手上已有一张执行中的单（计时在跑），从大厅再点【委托】→ 派单板 → 长按指纹接第二单 → **执行面板直接换成新单**：计时归零、证据槽清空、已挂道具标记消失，**全过程零提示**，前一张单连同它的进度无影无踪。

**复现**（MuMu，坐标按 780×1688）：
1. 大厅点【委托】(658,1478) → 长按指纹 (470,1430) 1.2s 接下 → 执行面板（记下 `执行中 · REMEDY` 与计时）
2. 点【收起 ▾】(680,1600) 回大厅（计时不停，顶部留「执行中 00:05」药丸）
3. 再点【委托】→ 菜单卡换成下一张 → 长按指纹接单
4. 执行面板变成 `MAIN 3/3`、`00:02`、证据槽全空 —— 前面那张补救单没了

**证据**：`78_exec_A.png`（REMEDY 00:02）→ `81_exec_B.png`（MAIN 3/3 00:02）；同族问题 docs/36 的 P0-4。

**根因（已定位）**：
- `quest_flow.dart:623-625` `accept()` **不判 `_active`**，直接覆盖（`_active = ActiveQuest(...)`）。
- `main.dart:1366-1368` 派单板 `onAccept` **只查 `_busy`**；
- 而**同一件事在主线页是拦住的**：`main.dart:2560-2561` 查 `_flow.active != null` 并插话「手上还有一张没交。先把它了了。」→ **同一个操作两套守卫**。

**建议修法**：守卫上提成一处（例如 `accept()` 返回 bool / 或派单板复用主线页那段判断），两处入口都走同一条；`accept()` 加 `if (_active != null) return false;`。
⚠️ 修的时候注意 `main.dart` 里「接单必须只走 `_beginExec()` 一条老路」的既有踩坑注释。

**验收**：执行中 → 收起 → 委托 → 长按接单 → **应被拦**（她说「手上还有一张没交」），且原单的计时/证据/道具标记原样还在。

## B2 · P1 · 开机自检首屏「链接宿主档案」永远是 demo 值

**现象**：冷启动第一屏的自检日志里那行

```
› 链接宿主档案 …… 林深 · LV7
```

**与存档无关**：清档（应显示"未找到 · 新宿主"）和已有存档（真值 `宿主 · LV1`）**两种情形显示的是同一行**。这是用户每次冷启动看到的第一行字。

**证据**：`crop_boot_both.png`（上＝清档那次 `01_boot.png`，下＝有档那次 `36_cold_boot.png`，日志区逐字相同）。

**根因（已定位）**：
- `main.dart:1784` `BootScreen(host: '${_host.name} · LV${_host.lv}', onWake: _wake)` —— `_host` 在首帧还是 `HostState.demo`（`host_state.dart:85`：`name: '林深', lv: 7`），读档（`_restore`）是异步的，还没回来就上屏了；BootScreen 那行字是挂载时按打字机播的，之后也不会改。
- 同源问题 docs/36 的 P1-6（读档竞态）。

**建议修法**：把首屏那行改成**由存档就绪状态驱动**：未就绪 → `链接宿主档案 …… 读取中`；就绪 → 真值 / `未找到 · 新宿主`。或让 BootScreen 在 `_restore` 完成后重建这一行（打字机重播那行即可）。

**验收**：清档冷启动应显示「未找到 · 新宿主」；有档冷启动应显示「宿主 · LV1」（与 HUD 一致）；不许再出现「林深 · LV7」。

## B3 · P1 · 输入幕没有常驻出口（三处）

| 场景 | 实测 | 代码 |
|---|---|---|
| ① 首次绑定 · 访谈卡 01/03→03/03 | **完全没有取消/返回**（屏上无按钮），目标说错/类别选错只能杀进程 | `main.dart:1658` 只给 AskField 传了 `onCancel`；`interview_deck.dart` **零** `onCancel` |
| ② 主线页【换目标】输入幕 | 有取消，但是**牌列里的牌**「CANCEL · 算了，不换」（`ask_field.dart:233-241`），藏在牌列**最右端**，默认只露出一角（`70_change_goal.png` 右侧那条边）—— 要横滑才找得到；屏上没有常驻取消键 | `ask_field.dart:258-260` → `_cancelGoalChange` |
| ③ 两处按**系统返回键** | **直接退出 App 到桌面**（进程还在，不是回上一屏、也不是取消当前输入幕） | 无 `PopScope`/`WillPopScope` 拦截 |

**证据**：`70_top.png`（换目标幕顶部 y0–400 干净无按钮）、`70_change_goal.png`（牌列最右那张只露一角）、`71_back_from_change.png`（返回键 → 桌面）。
**旁证**：docs/36 的 P1-8（访谈只能前进）—— 真机实测成立。

**建议修法**：① 给 `InterviewDeck` 补 `onCancel`（复用 `AskField` 那张取消牌的语言）；② 换目标幕把取消**提到常驻位**（例如输入条右侧一枚「取消」斜切键），牌列里那张可留可撤；③ 三处都用 `PopScope` 把系统返回键接成「退出当前输入幕」，而不是退出 App。

**验收**：访谈中途能退回目标输入；换目标能一键取消且主线原样；在这两幕按返回键 = 回上一屏，App 不退出。

## B4 · P2 · 结算出口轨第二张牌不露头、侧牌只露一条边（待复核）

**现象**：结算播完弹出的出口轨（`再来一单。/ 先歇会儿。/ 收工。`）只看得见**领位那张牌**，第二张被完全挡住；横滑一下才换领位（`21_settle_end.png` → `24_rail_swipe.png` 已证横滑有效）。我另外点了两次"侧牌露出的边"（625,1445 / 680,1480），**领位没换**。

**为什么记"待复核"而不是直接判 bug**：
- 约定是「点侧牌 = 把它送到领位」（`choice_rail.dart:185-190`），所以不换位就是不符约定；
- 但同一处 `choice_rail.dart:204` 写明**侧牌只露出让位的那条边**（`侧牌向右阶梯缩进 + 下沉 + 压暗`，`:20`），可点面积本来就窄，我两次点空也完全可能（本轮已两次因坐标估算出错误判，见 §非问题）。

**建议**：复核时先在结算页打 100px 网格量准侧牌的可点区再点；若确实无效，查 `ChoiceRail` 的 `kCardSideTapCommits` 与命中区。**不管结论如何，「第二出口不露头」本身值得改**：现在玩家要发现「先歇会儿」只能靠横滑或运气，建议让侧牌露出半个牌面。

**验收**：结算出口轨上的**两个**出口都能被首次看到的玩家发现并使用。

## B6 · 进出委托板闪一帧（换族平台视图错位）—— **本轮已修**

**一句话**：`kViewFamilies = [1.05, 1.70]` 而只有派单的 `talk` 用 1.70 族，所以每次进出委托板，**平台视图的布局矩形真改尺寸**（780×2870 ↔ 780×1772）；缩小那一帧 Flutter 已按新矩形合成、原生侧还按旧 surface 出图 → 她被渲染成「小号 + 错位」。

**已实现**：新增 [`app/lib/stage/redraw_veil.dart`](../app/lib/stage/redraw_veil.dart)，在 `main.dart` 挂在**她之上、环场之下**：换族那一帧起遮罩**满不透明约 3 帧（≈50ms）**→ 100ms 软退，期间一道青色扫线自下而上掠过。reduced-motion 下不播扫线、只做 3 帧静态切换。
**为什么是 3 帧**：实测平台视图要 **2~3 帧**才换上新 surface（只盖 1 帧时，第 2/3 帧还能隔着半透明遮罩看见"小号她"）。
**验证**：`rec6.mp4` 4 次换族处均「约 4 帧不可见 → 带扫线恢复」，全片无错位帧；`flutter analyze` 0 issue、既有 61 项测试通过；`rec5.mp4`（`animator_duration_scale=0`）同样覆盖。
**全文与分析过程**：[docs/37 §3.5](37-全流程操作手册.md)。

**留给你的一个决策点**：现在每次进出委托板，她会有约 50ms「不在场」再扫回来（只压她、不压屏，环场/HUD/台词都在）。若觉得这一拍太"掉线"，两条替代（都在 docs/37 §3.5 留档）：
- 换成**亮帧**（全屏白闪 16%/180ms，docs/08 的既有语言）而不是压暗；
- 退回**单族** `kViewFamilies = [1.70]`：结构上永不再 resize，代价是常驻 GL surface 从 1772px 高变 2870px 高（≈2.6× 像素）。

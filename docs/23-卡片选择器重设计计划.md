## 3 · 共同手感法则（两套都遵守）

这两条是宿主点名的关键词，写成硬约束：

### 3.1 悬停抬起（lead lift）

- 任一时刻卡组里**恰有一个「领位」**（lead）= 当前选中项。
- 领位项：`translateY: -10 ~ -16px` + 轻微 `scale 1.03` + 一层青色外发光（`C.blue α60, blur 22`）。
- **手机没有真 hover** —— 宿主已确认，这里的「悬停」= **选中/领位即抬起**。
  （不额外实现 pointer hover；将来若上 Web/桌面再补一份。）

### 3.2 领位让位（neighbour yield）

- 非领位项按**离领位的距离**分级退让：下沉 `+4 ~ +8px`、`opacity .5 ~ .6`、`scale .88 ~ .92`。
- 「让位」必须是**双向**的：领位向前抢，邻位向外/向后缩 —— 不是各自独立缩放。

### 3.3 切换 = 滑动 + 音效 + 轻震（一拍到位）

| 事件 | 音效 | 震动 |
|---|---|---|
| 换领位（滚动一格） | `rung`（甲）/ `tap`（乙） | `Haptics.buzz('choose')` |
| 确认选中 | `seal`（甲 · 使用道具）/ `choose`（乙 · 回应） | 对应 key |

**不新增音效素材**（新增 key 才要走 `tools/audio/` → `app/assets/audio/` 烘焙，本轮不需要）。

### 3.4 动效实现纪律

1. **只动 `Transform` / `Opacity`** —— 不触发布局重排，禁止用 `AnimatedContainer` 改尺寸做过渡。
2. 位移曲线用 `kOut`（350~420ms）；过冲用 `easeOutBack`（≈1.08）或真源 `Spring(k:120, zeta:.9)`。
3. **错峰入场**沿用面板页语言：0 / 60 / 120ms。
4. `MediaQuery.disableAnimations` 为真（系统「减弱动态效果」）→ **直接落终态**，不挂动画。
5. **命中区纪律**：展开/收起时用 `IgnorePointer(ignoring: !open)` 断命中 ——
   本仓库真踩过「一颗看不见的按钮替派单板的指纹挨点」，这条不许省。
6. **可读性铁律**：退让项的缩放不得让正文等效小于 13px；乙套因此**干脆不缩放**。

## 4 · 甲 · 「物件台」——选择道具

### 4.1 立意

道具是**实体物件**，所以甲套走**厚卡 + 摊牌**：像把三件东西摊在台面上，
中间那件被推到你面前抬起来，旁边两件**向外旋开让位**。

### 4.2 形态

- 外壳：**保留现有 `.drawer` 玻璃壳**（描边 / 阴影 / 上移 14px 入场一字不改），内部由 2 列网格换成**一条横向物件台**。
- 卡（竖版物件卡）：普通位 **96×124**，领位 **104×136**（缩放表达），圆角 12。
  - 右上角：mono 小字角标（`道具` 编号或类型）。
  - 中央：**44px 圆环 glyph**（复用现有 `_glyph` 的圆环 + 径向辉光 + 外发光语言，放大）。
  - 下方：名称（cn 13）+ 持有数（mono 10：`持有 ×N` / `已生效`）。
  - 底部：一条 2px 状态条 —— 已生效 = 青色实心发光 / 可用 = 暗青 / 无货 = 灰。
- 排布：3~5 张横排，间距 10；**领位居中**，左右各**向外浮动**：额外横向偏移 ±14px + **旋转 ±4°** + 下沉 6px + 压暗 `.55`。
- 「去补给」**不进卡组**（它不是一个物件）：留在物件台**右侧**当一枚独立的斜切小键，金币不足走现有禁用态。

### 4.3 交互

- **左右拖拽换领位**：`onHorizontalDragEnd` 判方向 + 速度，吸附到最近一格（速度超阈值则翻一格）。
- **点侧卡** = 把它送到领位（不是直接使用）。
- **点领位卡** = 使用（语义等同现在的 `onUse(id)`，回调签名不变）。
- 使用那一拍：领位卡向上弹一下（`-6px` 过冲）+ 青色亮帧 + `seal` 音 + `seal` 震，卡面状态条转实心「已生效」。

### 4.4 边界态

- 只持 1 件 → 单卡居中领位，左右留白，不硬撑。
- 全部无货 / 已生效 → 全部灰 + `opacity .35`（沿用现有 `disabled` 语义）。
- 抽屉再点一次「道具」收起 → 行为不变（`_drawerOn` 翻转）。

## 5 · 乙 · 「铭牌轨」——回应

### 5.1 立意

回应是**她的三个方向**，不是物件 —— 所以乙套走**薄牌 + 抽牌**：
像档案柜里一排斜切铭牌，被选中的那张**抽出来领位**，其余**向右阶梯缩进**。

### 5.2 形态（与甲刻意不同）

- 卡形：**横版斜切铭牌**，约 **268×58**（不是甲的竖版厚卡）。
- 斜切：左上 / 右下各切 12px（`ClipPath` + 自定义 `CustomClipper`，即 DESIGN.md 的斜切角语言）。
- **不缩放**（保证 15.5px 正文可读）—— 领位完全靠**位移 + 明暗 + 亮边**表达。
- 领位：**左对齐到边**（`left: 20`）+ 抬起 `translateY: -8px` + 满亮 + 左侧 **3px 青色竖条** + 斜切高光点亮。
- 让位：其余牌**向右阶梯缩进 14px × 序数** + 下沉 6px + 压暗 `.5` + 高光熄灭。
  → 2 条时是「一前一后」，3 条时按距离递减。
- 排布：**横排**（不是现在的竖堆），整叠看起来像**错开的斜切牌**。
- 保留「宿主」小牌与主/副选项的实心/描边区分（原型语义不丢）。

### 5.3 交互

- **左右滑动整叠**移动领位：拖动时把 `dx` 映射到各牌 offset，松手吸附最近领位。
- **点任一条** = 直接领位并确认（一步到位，不要求先滑后点）。
- 确认那一拍：领位牌**向左滑出**（`translateX: -28` + 淡出）+ 沿用现有 `Sfx.play('choose')` + `Haptics.buzz('choose')`。
- **`_locked` 语义与 `Choice` / `onPick` 签名一字不改**（原型 `choose()` 的「点一次就锁死」）。
- 收起（`visible=false`）：整叠向下 28px 淡出，保留现有 300 / 500ms 节奏。

## 6 · 为什么这两套「不相同」（对照表）

宿主明确要求两个设计不能相同，逐维度对照如下：

| 维度 | 甲 · 物件台（选择道具） | 乙 · 铭牌轨（回应） |
|---|---|---|
| 卡形 | **竖版厚卡** 96×124 → 104×136 | **横版斜切薄牌** 268×58 |
| 排布 | 横排居中轮播 | 横排错位阶梯 |
| 领位表达 | **放大 + 抬起 + 旋转归零** | **左移领位 + 亮边 + 斜切高光**（不缩放） |
| 侧项退让 | **向外浮动 + 旋转 ±4°** + 压暗 | **向右阶梯缩进** + 下沉 + 压暗 |
| 材质感 | 厚（圆角、角标、状态条、辉光） | 薄（斜切、单线亮边、mono 编号） |
| 换位音效 | `rung`（滚档） | `tap`（轻点） |
| 确认音效 | `seal`（生效） | `choose`（沿用） |
| 语义 | 挑一件**东西**用掉 | 挑一个**方向**走下去 |

一句话：**甲是「摊牌」，乙是「抽牌」**。

### 8.2 交给宿主人工测的（手感必须真人看）

> 手感这件事我这边只能验「跑得起来」，**验不了「爽不爽」**。以下清单请你在 Mac/模拟器上过一遍：

1. **回应（结算页 / 失败页）**：左右滑动 → 中间那张是否**抬起来更突出**？旁边的牌是否**阶梯让位**？切换有没有 `tap` 音 + 轻震？点一条是否一步确认并左滑出？

3. **选择道具**：执行面板 → 点「使用道具」→ 物件台是否横向摊开、中间那张抬起、两侧向外旋开？
   左右拖拽换领位是否跟手？点侧卡是否送位？点领位是否使用并响 `seal`？
4. **道具 · 边界**：只有 1 件 / 0 件（禁用灰）/ 已生效（实心状态条）三种状态。
5. **两套放一起看**：是否**一眼能看出是两种不同的设计**（甲摊牌 / 乙抽牌）？——这是宿主的核心要求。

### 12.3 计划书中与实现不符、被就地修正的三处

1. **§4.2 甲套几何算不平**：计划写「普通位 96×124 + 间距 10 + 右侧去补给键」，但抽屉内可用宽只有
   **332px**（390 − 14×2 − 14×2 − 2），348px+ 装不下，侧卡会被裁掉、点不到。
   经宿主裁决 → 卡缩到 **86×112**、间距 8、stride 94、视口 266、「去补给」键 60，合计正好 332。
   （宿主选项原文：「缩卡到 86×112 + 加横向滚动（推荐）」）
2. **§3.4-6 可读性铁律与 §4.2 自相矛盾**：计划既要求「退让项缩放 .88~.92」又要求「等效正文 ≥ 13px」，
   而名称字号写的是 13 → 13×.88 = 11.4px 不达标。修正为**名称字号 15 × 侧卡缩放 .88 = 13.2px**，
   并在 `item_rail_test.dart` 里钉住 `kItemNameSize * kItemSideScale >= 13`。
3. **§8 测试范围漏了两处必红**：`fail_test.dart` 的竖堆盒模型断言（`height 109`）与
   `item_drawer_test.dart` 的「四格」直接 tap 断言，都会因形状改变而失败。
   经宿主裁决 → 改这两个测试适配新形状。
   **实际结果**：`fail_test.dart` 改了（几何那条）；`item_drawer_test.dart` **一个字符都没改** ——
   甲套最终采用的几何让三张卡 + 「去补给」在不滚动时全部可见可点，冻结断言原样成立。

### 12.5 ⚠️ 两处「点一下到底算不算确认」的语义分歧（**请宿主裁决**）

计划书 §4.3 / §5.3 写的是「点侧卡只送位、点领位才确认」，但两套**最终落地的行为不一样**：

| | 甲 · 物件台 | 乙 · 铭牌轨 |
|---|---|---|
| 点侧卡/侧牌 | **送位 + 立刻用掉**（一步到位） | **只送位**（两步） |
| 点领位 | 使用 | 确认并滑出 |
| 开关 | 无 | `kSideTapConfirms`（默认 `false`，一行可翻） |

- **乙** 保留了两步，理由是：让位牌只露出 L 形窄边，拿它当「确认」＝点领位牌下缘偏 10px 就选错方向且不可撤销。
- **甲** 被**冻结测试**（`item_drawer_test.dart`「有货的照常」）逼成一步到位：该断言直接
  `tester.tap(Key('exec.drawer.crit'))` 并期望回调，而 `crit` 在新形态下是侧卡。
  改成两步就必须动那条冻结断言 —— 而计划书 §8.1 只授权改两个测试、不含它。
- **风险**：甲套「滑到一半顺手点一下旁边的卡」会**直接消耗那件道具**，且不可撤销。
- **若宿主想要两步**：把 `ItemRail._onTapUp` 的侧卡分支去掉「再用掉它」那半句，
  并把 `item_drawer_test.dart` 那条断言改成「先 tap 侧卡 → 再 tap 领位卡」即可（约 10 行）。

### 12.6 没验的（不声称验过）

1. **手感「爽不爽」** —— 只能验「跑得起来 + 形状对」，爽度必须宿主在 Mac/真机上过一遍（§8.2 清单仍然有效）。
2. **音效/震动的真实发声**：widget 测试无平台插件，`Sfx`/`Haptics` 走「永不抛」路径；
   真机上没听（模拟器音频不可靠）。调用路径与前置条件已由测试钉住。
3. **系统「减弱动态效果」开关**：代码里每处动画都接了 `railReduceMotion → Duration.zero`，
   但**没写翻开关的测试**，也没在模拟器上开这个开关实测。
4. **真字体字形**：测试与 golden 用的是兜底字形（中文是方块），只验了形状/配色/错位，没验真实排版。
5. **左右拖拽换领位的跟手感**：`settleIndex` 有 7 条纯逻辑单测，但「跟手拖 + 松手吸附」的实机手感没验
   （模拟器上我只做了点击与滑动换位，没做连续拖拽观察）。
6. **全量像素回归**：按宿主明示**没跑** `tools/ref/drive.ps1`。
   **这两处 UI 是有意改动，像素基线预期会变** —— 下次跑回归时 `choices` 与 `drawer` 两页的差异属预期。

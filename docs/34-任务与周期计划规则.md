## 1 · 一句话

**目标** = 一句话 + 期限 + 一张任务清单；**任务**是唯一的工作单元；
**周期计划**按期限把任务排出来，一天一张，最后一张是兑现单。

```
旧： 目标 = 一句话 + [8 个环] + 天数     环 = 数据结构 + 工作单元 + 视觉（三合一）
新： 目标 = 一句话 + 期限 + 清单         任务 = 唯一工作单元
     清单条数 = 期限天数（最后一张 = 兑现单）
```

## 2 · 数据模型（`lib/state/`）

### 2.1 `Goal`（`goal.dart`）

| 字段 | 含义 |
|---|---|
| `text` / `short` / `cat` / `interview` | 目标一句 / 天幕短字 / 类型 / 访谈答案（沿用） |
| `at` | 立目标时刻（**换目标时沿用**，O-2） |
| `days` | **期限天数**（旧语义是"环数"，已改） |
| `plan` | `List<PlanTask>`：期限内的任务清单 |
| `uid` | 显式身份（演示档 `'demo'`）；一般留空，`id` 按 `at` 推 |

读数：`doneCount`（已完成条数）、`totalTasks`（清单条数）、`firstOpenIndex`
（第一张没做完的，-1 = 全走完）、`passedDays` / `remainingDays` / `progressText`。

### 2.2 `PlanTask`（`goal.dart`）

`index`（计划内序号，0 基）、`short` / `title` / `proof` / `minutes` / `rank`、
`attrs`（六维加成，**生成时定死**，结算只读）、`state`（`todo / active / done / abandoned`）、
`finalTask`（兑现单）、`held` / `doneAt`（完成后记）。

### 2.3 `Quest`（`quest.dart`）

`ring`/`ringTotal` → **`planIndex` / `planTotal`**（日常/补救 = -1 / 0），
新增 `goalId`（这张单属于哪份清单；日常/补救为空串）。主线单只对**同一个**
`goalId` 的清单起作用 —— 换过目标的老单不许动新清单。

### 2.4 老存档迁移

`Goal.fromJson` 读 `plan`，读不到就退读 `rings`（`RingState.cur → active`、
`lock → todo`、`finalRing → finalTask`），并把期限按**清单条数**兜底
（别把旧档里的"8 环"当成"8 天"）。`questFromJson` 同样兼容旧的
`ring`/`ringTotal` 键。合并式迁移的既有纪律不变：缺字段走默认，坏档不崩。

## 3 · 周期计划（`goal_gen.dart`）

- **条数 = 期限天数**：`planTaskCountFor(days) = clamp(days, 2, 400)`。
  最后一张是**兑现单**（`finalTask = true`，S 级，整条计划里最重）。
- **期限从哪来**：`goalDaysFor(text)` 读时长的词 —— 一年 365 / 半年 180 /
  N 个月 N×30 / 百天 100 / 八周 56 / 一个月 30 / 两周 14 / 十天 10 / 一周 7；
  一个都没命中 = **21 天**（默认，不再猜"6 环"）。
- **档位阶梯**：`planRankAt(i, n)` 低开高走，收在 S（兑现单永远 S）。
  **首目标例外**：3 天 3 张，锁定 E/D/C（docs/05）。
- **内容两条路**：
  ① LLM 交上来的**任务池**（`planned`）—— 池子有几张就循环用几张：
     周期性计划本来就是"同一件事做 N 次"，所以「半年健身」是 6 个动作循环
     90 次，而不是让模型硬编 180 条；
  ② 类别模板（`GoalCategory.firstTasks`）+ 加码段（`seed × 1.35^k` 与
     「到此为止最重 +5」取大，**单调不减**）。
- **六维**：按类别倾向 `cat.tilt` 与档位点数 `Rarity.of(rank).pt` 走
  `QuestFlow.splitAttrs`（旧实现硬编码全押「体」，已废）。
- **前 10 任务必胜**（docs/05）不变：首目标 3 张全在 F~C 档。

**让模型交几张**：`planDraftCountFor(days)` —— 期限 ≤14 天就交满（一天一张），
更长的目标交 **8 张的任务池** 由计划循环排。

## 4 · 发布与执行（`quest_flow.dart`）

- **发布窗口**：队列里同时挂 `kPlanPublishWindow = 3` 张还没做完的计划单；
  其余的在主线页上显示「**待发布**」。完成一张 → `publishPlanTasks()` 补一张，
  始终保持在手 3 张。`publishPlanTask(i)` 可以把某一张**单独**派出来
  （宿主在主线页按住「待发布」那条也能直接接）。
- **顺序锁不存在**：`accept()` 从不判顺序，清单里任意一张未完成的都能接。
  同一时刻仍然只有一张在执行（`_active` 只有一个槽）。
- **接单** = 拔单即开始计时（`accept` 记 `startAt`，计时由它推导）。
- **执行页道具**（`dbl / crit / shield`）不变。
- **认输**：主线单不判死，回到队列；清单里那张保持未完成。
- **换日**（`rollDayQueue`）：隔夜日常与主线单作废、补救单留未过期的，
  之后 `publishPlanTasks()` 重钉（幂等）。

### 4.1 结算

- **逐单结算**口径**零改动**：经验 / 金币 / 六维 / 连击 / 暴击 / 称号 /
  补救半价 / 执行历史，全部照旧（数值真源 `lib/data/rewards.dart`）。
- **里程碑结算**：交掉**兑现单**（或清单全部完成）= 这个目标完成 →
  `finale = true` → `_applyFinale`：铸下一份计划（`buildNextGoal`）、撤下旧主线单、
  把新计划的在手窗口补进队列，`FinaleOutcome` 交给结算页说一句话。
- 提档条件读的是 `cleared = doneCount` / `total = plan.length`（旧代码读的是"环号+1"）。

## 6 · 进度带（`lib/stage/progress_band.dart`）

她身上原来那 **8 条等宽虚线椭圆**（脚踝 → 肩）换成**腰间一条进度带**：

- **暗轨**（虚线）= 清单上还没做完的部分
- **亮弧**（实心发光，从右端起逆时针走）= 已完成的比例；弧头一颗彗星 = 你现在的位置
- **走满** = 整圈实心（这个目标兑现了）

纪律不变：**状态一律用样式表达，禁止状态文字**；开机 34% 亮度、唤醒时
一次性点亮（原 8 环逐拍 → 1 拍 420ms）、失败时掐暗三下（0 / 90 / 200ms）。

大厅里那枚挂签由 `RingTag`（`R5/8`）改成 `PlanTag`（`4/8 单` + 目标短字），
点它开主线页 —— 位置仍挂在进度带右端（大厅相机）。

## 7 · LLM 拆解 → **拆计划**（`lib/agent/mainline_tool.dart`）

- 工具名 `set_mainline` → **`set_plan`**；入参 `rings` → **`tasks`**。
- schema 里说清：交的是一批**单次可执行**的动作（不是"坚持一个月"），
  长目标交的是**会循环执行的任务池**，最后一张写能证明目标达成的验证动作。
- 条数必须正好 `taskCount`（= `planDraftCountFor(days)`），不对就 fail 让她重来。
- 🚫 她**不决定**档位阶梯、时限上限、兑现单 —— 那些是 `goal_gen` 的规则，
  工具只保证"形状对"。
- 兜底铁律不变：没 Key / 无网 / 她把工具用糊了 → 逐字退回类别模板。

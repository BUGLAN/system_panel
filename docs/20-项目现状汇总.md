## 2 · 困境

### 2.1 平台限制

**① Live2D 原生渲染在 MuMu 上被 emugl 转译层阻断（硬止损，非我方缺陷）**

- 现象：`loadModel` 成功（第 2 次重试 true）、视图在树且尺寸正确（`Live2DTextureView{... 0,0-1080,1080}`）、**但角色不绘制**。
- 根因（t7 attempt2 二分定案）：渲染线程每帧刷 `emuglGLESv2_enc GL2Encoder s_glEnableVertexAttribArray / s_glVertexAttribPointer → GL error 0x501 (GL_INVALID_VALUE)`——插件的顶点属性提交在 MuMu 的 emugl 转译层上**每次都失败**；裸舞台二分实验（`SysApp.kStageBareProbe`，无任何 Flutter 层）依旧全黑并崩进程，**排除合成/层序/我方视图树**；插件源码核查确认 GL 0x501 出自 C++ 顶点提交，Dart/Kotlin 层无开关可绕。结论：`flutter_live2d 1.0.2` 的 C++ 渲染管线与 emugl 不兼容，**修它等于改插件 C++（workspace 外，pubspec 锁 1.0.2）**。
- 现状处置：`main.dart` `kNativeStage = false` 默认走 WebView；原生实现全量保留（几何相机 + `StagePort` 双实现 + `stage_port_test` 12 例），**翻回 = 改一个常量**。翻回三条件：插件升级 / 换非模拟器 GPU 栈（真机）/ MuMu 换图形转译模式。
- 指针：`../app/STAGE-OPTIONS.md`「MuMu · 原生舞台复验」节 +「attempt 2 追加」· 证据 `../.verify/t7/01~07`（含 264MB `logcat-bare.txt`）· 提交 `bec8f7c`、`7bfd774` · CHECKLIST §6。

**② WebView 路线的代价（当前在用的那条）**

- 多一个 **225MB** 沙箱进程、舞台中位帧 **89ms ≈ 11 FPS**（HANDOFF 数字，模拟器口径）。
- **性能口径割裂**：`dumpsys gfxinfo` 只统计 Flutter 视图，Live2D 画布在 WebView 合成器里**不计入**——所以「p99=6ms、0% janky」是 Flutter 侧的健康读数，**不能**用来证明舞台流畅（MOTION-ANALYSIS §0 已声明）。
- 副作用：平台视图外不能套 `Transform/Opacity`（saveLayer 会吞掉平台视图），`fx_layer.dart` 的 `ShakeLayer` 必须保持「不抖就不套 Transform」，动效设计被这条纪律约束（HANDOFF 第 4 条 + `fx_test` 断言）。

**③ MuMu 环境摩擦（每次验证都要付的成本）**

- `wm size/density` override **MuMu 重启即丢**，每次起模拟器先重跑两条命令（ENV.md）。
- **真·飞行模式会杀死 MuMu 的 adb 桥**（TCP 转发随客机网络栈断），断网测试只能走坏 Key/无 Key 等价路径（CHECKLIST §4 环境注）。
- `screencap` 有 ~1s 管线延迟，**<450ms 的过渡中帧抓不到**——结算/对话层滑入的中帧证据只能靠代码常数（MOTION-ANALYSIS 口径声明）。
- 无软键盘 → 键盘避让不可实测（TODO-30）。
- 多成员同时跑 `flutter analyze`/`flutter test` 会互相等启动锁（ENV.md 并发提示）。

## 3 · 优点（差异位：凭什么赢）

1. **关系型产品定位，不是工具**。唯一把「习惯养成」包进**网文系统流叙事**（绑定/等级/稀有度/主线环）+ **有记忆、能替你操作的 AI 系统娘**里的产品——竞品在做工具，本产品在做关系（docs/19 §3.3 差异位表）。
2. **拍照 + AI 视觉校验，竞品独一份**。证据槽 ≤3 张 → 压缩 JPEG80 → 多模态判定 → `已校验/存疑+note/未校验` 三态角标 → **暴击率 7%/4% 联动**（`vision.dart` `evidenceCritBonus`，封顶 .85）；无 Key/断网/超时/坏 JSON 四情形全兜底，**校验失败永不阻塞提交**（docs/18 §2.4）。
3. **agent 工具注册表可扩展到应用内任何操作**（A3 已接线兑现）：六工具 + function calling 循环 + **无 LLM 也能用的快捷 chip** + 〔工具〕系统条目入历史 + 安全钳制（工具不可直接改经验/金币，数值只能经结算）——这是「对话即操作」从死代码变成真功能的完整闭环（`tools.dart:300`、`context_adapter.dart`）。
4. **动效纪律是资产，不是负担**。动效真源 `prototype/motion-demo/index.html` + AGENTS.md 动效参数表；实机 p50=5ms/p99=6ms、**0% janky**（4711 帧采样）；MOTION-ANALYSIS 的「合规项」节逐条留档（亮帧 16%/180ms、count-up 800ms、按住三件、落板过冲关键帧、失败氛围、她的表演）——**免重复审**。
5. **测试文化成规模**：246 → **524**（+113%），全离线 mock（`MockClient`/`InMemorySharedPreferencesAsync`/注入 picker），零真网零真盘；`analyze` 常绿是提交前置条件（ENV.md 验证纪律）。
6. **兜底铁律贯穿全部 LLM 触点**：文案四入口逐字回退 LINES、聊天固定 5 句、视觉四情形标未校验——**「提交卡死」类事故零容忍**被写进设计原则（docs/18 §二 总原则）。
7. **文档纪律**：先文档后代码；`docs/18` 施工真源（含文件级分工表 + 单写者纪律 + main.dart 串行时序）、`docs/19` 产品分析、MOTION-ANALYSIS、CHECKLIST、ENV.md 各司其职，**每条断言可复核**（这也是本文能逐条给指针的前提）。
8. **空态/错误态达标**（docs/19 §A11 点名表扬）：空队列「今日已清」拒绝进板、无 Key 视觉零等待、测试连接带服务器原因、断网聊天固定兜底句不卡 UI、拍照回流与坏档自愈。

## 7 · 附录：决策评审（gate · GLM 5.3 MAX · 2026-10-09）

> 任务 t23。评审对象：§5 TODO 总表 32 项。三件事：优先级裁决 / 下一批组合 / 演出时长规格冲突裁决建议。**本文只裁决与建议，不动代码**；最终拍板权在宿主。

### 7.1 优先级裁决

**① 通知（TODO-02）vs 内容耗尽（TODO-03）：谁是留存第一杀手？**

裁决：**通知是结构性第一缺口，但它的价值上限被 TODO-01 压制——所以「第一杀手」其实是最上游的叙事终点（TODO-01）**。推理链：

- 习惯类产品的本质是「在用户不在场时替他守住承诺」。当前产品在锁屏上**完全失声**（§2.2-5）：清晨钉单、截止提醒、连击保卫全部依赖用户自己想起来。这是产品结构缺口，不是功能缺口——**通知保 P0 无争议**。
- 但给谁发通知？第 4 天主线 finale 后**主线永久熄火**（TODO-01），用户只剩 18 条池子的日常——此时一条「今天的单钉好了」的提醒，是把用户带回一条**已经走完的路**。通知是放大器：回路有多深，它就有多值；回路在第 4 天断，它就放大「没内容」。
- 内容耗尽（TODO-03）是**关系质量的第二序杀手**：D9~18 才显形，但它咬的是本产品的差异位（「她嘴上新、手上一套旧单」直接拆「关系」人设）。且 TODO-01 不修会让它提前——主线熄火后日常池是唯一内容源，重样期实际前移到 ~D6-9。

∴ 实施顺序：**TODO-04（半天止血）→ 批次二（TODO-01 + TODO-03 的 S 半）→ 批次三（TODO-02 + TODO-03 的 M 半 + TODO-07）**。两项都保 P0，但通知排在生命周期之后一批。

**② Live2D 真机翻回试验：近期值不值得排？**

裁决：**不排进近期批（P2 · 机会型），但把「硬件会话」固化成一张组合卡**。理由：

- 翻回三条件里唯一现实的是「真机 GPU 栈」，而宿主本机不接 Android 真机（AGENTS.md）——试验被硬件可用性 gate，不该占产品批次的名额。
- 一次试验的信息价值很高（原生实现至今没在任何设备上成功过；成了→「全面换原生」从止损变成路线，败了→永久关题、删翻回计划），但**用户价值眼下为零**：宿主自己的平台就是 MuMu（emugl），真机原生不改善宿主体验。
- 一个常被忽略的事实：WebView 路线的 89ms/225MB 是 **MuMu 口径**——真机 GPU 会显著改善 WebView 合成，等于「零成本自动好转」。原生翻回的真实收益要在真机 WebView 表现测完之后才知道，顺序应是：真机先测 WebView → 不够好 → 再翻原生（STAGE-OPTIONS 复验清单现成，30 分钟）。

### 7.3 「结算演出 3.85s 超规格」裁决建议

**建议：改文档（以原型为真源），但把规格从「单段上限」升级为「分段规格 + 跳过护栏」——不是二选一，是把两个真源打架的原因修掉。**

推理：

1. **项目宪法已回答了「谁是真源」**：AGENTS.md 动效节明文「动效真源 = prototype/motion-demo（真机的唯一标准），参数不许凭感觉改」。实测 3.85s 是对 opus-v2 结算编舞的忠实复刻（多拍：砸印→count-up→涨条→档位台词→出口选项），≤1.6s 是 docs/08 时代写在编排进化**之前**的旧数——**按项目自己的裁决规则，原型赢**。
2. **但「原型赢」不等于「3.85s 无罪」**：规格的本意是「别拖」，而 3.85s 的真实风险不在单次长度（0% janky、内容撑得住），在**重复观看不可逃**：日上限 6 单 ≈ 23s/天不可跳过仪式。压缩时长会砍内容（丢拍=丢手感），加跳过/快进才两全。
3. **具体修订建议**（宿主可直接采纳的文本）：
   - 结算：`首关键帧（印章+首个数字到位）≤1.6s；全演出 ≤4s；同日第 2 单起自动快进至 ≤2s；点按任意处跳至出口选项`。
   - 发布：`首拍（落板稳定）≤1.2s；全揭晓 ≤3.5s；fast 档 ≤2s；点按跳过常开`。
   - AGENTS.md 动效参数表加一行：「时长规格以分段口径为准（docs/20 §7.3 裁决），单段总长数字以原型实测为真源」。
4. 采纳后 TODO-10/11 从「待裁决」转为批次五可执行（文档 S + 跳过实现 S）；若宿主坚持 1.6s 硬规格，则属于**有意推翻原型**的宿主决策，施工按「保形缩时」做（落板过冲关键帧不动、逐拍等比收），但应知道这与「原型即规格」的宪法条款冲突，需同步改 AGENTS.md 真源声明。
